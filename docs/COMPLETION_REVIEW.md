## 上游已经实现的语义

- 默认关闭，仅支持 print 和 JSON 模式；RPC、SDK stdio 和交互模式不能直接使用。
- 单独启用时，在本次调用的原始输入、图片及后续显式用户输入之后，最多追加一次
  自查提示。额度属于整次调用，不是每条 assistant 消息或每次 `agent_end` 一次。
- 使用原会话及其当时的模型与上下文，不创建独立 reviewer，不另开会话。
- 提示模型核对原任务覆盖、接口与类型、边界、最终 diff，以及最后一次修改之后的
  相关验证；可以补测试和修复问题，不只是输出一段评价。
- 独立自查不要求 Git 仓库、干净工作区或新提交。它不会额外要求提交代码，
  但原任务已有的提交要求仍然有效。
- 一次追加提示不等于一次模型请求：补测试、调用工具和修复可能产生多次推理。
  自查会额外消耗时间和 Token，不能宣称免费、固定费用或固定时长。
- 原工具权限与用户拒绝继续生效；自查不能把拒绝转换成允许。

`--completion-check git-committed` 是另一项能力。它检查新提交、提交内容变化、
工作区状态及最终文本；与自查组合时共享追加提示预算。第一版桌面接入不包含它，
不自动执行提交、清理工作区或为满足检查而处理无关文件。

## 终止与回执边界

上游不在以下情况自动继续自查：

- 本次调用出现终止性工具拒绝、assistant 错误或取消；即使原生重试后来成功，
  终止保护也不能被清除。
- `exit_plan_mode` 以结构化 `external_approval_required` 结果交接外部审批；
  交接不是用户批准，不能用自查绕过。
- 会话或工作目录被替换，或在等待输出期间取消／退出。

上游 JSON 的 `completion_check` 事件区分：

| 字段或状态 | 含义 | 不代表 |
| --- | --- | --- |
| `review.requested` | 已安排一次自查机会 | 提示已投递或已调用模型 |
| `review.sent` | 已观察到原自查文本作为该会话输入被投递 | 模型完成自查或任务正确 |
| `completed` | 有界自查流程结束且有最终文本 | 测试全部通过或独立验证通过 |
| `exhausted` | 追加机会耗尽后仍缺最终文本 | 自动获得下一次重试权限 |

扩展拦截、前置检查失败等情况可能造成 requested 为真、sent 为假。
不能把安排、投递、结束和正确性合并成一个绿色“通过”。

## 为什么桌面端不能直接打开参数

`cli/args.ts` 明确拒绝 RPC 模式的 `--completion-review`。现有
`RpcProcess.start()` 固定启动 `--mode rpc`，强行附加该参数会导致启动失败。

当前 RPC 的 `prompt` 在前置检查成功时回复接受回执，并不等待模型和工具全部结束。
原始 `agent_end` 也不等于整个桌面任务结束：之后还可能有原生重试、扩展续跑、
后台交接和真正的 `agent_settled`。不能在 React 收到结束事件时再临时发送
“检查一下”，也不能将 prompt RPC 的接受回执当成自查触发点。

Desktop 的 `session-runtimes.ts` 已基于运行代次、Goal 和后台任务门控完成通知。
接入必须让首次回答与自查属于同一个桌面任务，保留取消、退出和账户切换保护；
不能先发完成提示音／未读通知，随后悄悄再开始自查。

## 第一版实现范围

### 入口

复用现有权限选择器中的“任务”选项区，增加“完成后自查”的单次勾选项，
默认关闭，不新增常驻按钮、右栏或完整审查面板。

- 仅绑定下一次成功提交的普通主会话任务；提交失败不消费选择。
- 排队输入需要携带自己的选择快照，不因用户随后修改选项而串到另一条任务。
- 不设全局默认开启，不在应用重启后自动继续未完成的自查。
- 第一版不接旁问、子代理、Cron、Plan、Goal 或 Ultracode 自动轮次。
  任务进入审批交接或其他不适用状态时，应明确跳过，而不是冒充完成。
- 入口说明同会话自查可能补验证与修复、消耗额外 Token，不称为独立审查。

### 运行时

通过窄 Desktop 兼容补丁接入 RPC，复用上游自查提示和终止规则。
新请求字段与能力标志必须成对实现和测试；旧 runtime 不支持时禁用入口并明确提示，
不能让未知字段被静默忽略后仍显示已开启。

自查控制器位于运行时／主进程边界，不依赖右栏、组件挂载或当前可见会话。
控制器绑定原任务、会话、工作目录和执行代次，并遵守已生效账户、模型、思考和
权限，不提前应用下一轮预选，也不因失败切换供应商或计费方式。

先等待原提示的真实执行收尾，再决定是否投递一次自查。显式用户输入优先，
不得被自动自查插队。Desktop 队列中的新输入会通知控制器跳过仍待投递的自查；
已经开始的自查不因普通排队输入而中断，后续任务在其终态之后按序执行。
带自查选择的排队任务不能通过“立即发送”插入当前任务中间，选择快照在编辑和
失败重试时保留。停止、切换运行时或账户变化继续受整轮任务所有权保护。
取消、错误、终止性拒绝和审批交接的优先级高于“新输入优先”，不能被后者掩盖。
这些边界由控制器、真实 RPC 和 Desktop 队列测试覆盖。

### 正文与完成态

正文沿用原聊天的模型与工具结果展示。自动自查来源使用明确的结构化身份；
使用 `PromptOptions.customMessage` 投递，身份为
`desktop-completion-review-input`，包含版本、来源及本次自查 ID。
只有匹配结构化身份及上游原始提示时才记录 `sent`；提示不展开模板。
正文显示自动来源说明，不伪装成用户亲自发送的气泡；复制回答时不夹带内部提示。
终态保存在控制条目及 `desktop-completion-review-result` 中，重开历史可回看，
未结束的旧记录只标为取消，不自动续跑。

状态至少区分待自查、自查中、流程结束、失败、取消与跳过；“流程结束”
不显示为“验证通过”。自查失败保留原回答和诊断，不静默重试或自动扩大预算。
完成提示音及整轮尾态只在有界流程真正收尾后触发一次；清单完成动画仍保留
原有“清单完成”和“会话结束”的不同语义，不因自查强行伪造任务计数。
若历史写入失败，控制器仍发出一次明确失败的终态并释放运行状态，
不假报完成，也不因重复写入失败把会话永久卡在运行中。

自查产生的实际模型和工具用量进入已有会话统计，防止重复计入；不另造费用算法，
不夹带旁问用量归集或第三方价格功能。

## 实现验收清单

1. 默认关闭时原行为、事件流及模型调用次数不变。
2. 普通任务最多追加一次自查；多条模型消息、工具循环和重复结束事件不重复触发。
3. 验证补测试／修复、无 Git 任务、保留无关修改及不增加提交要求。
4. 取消、错误、终止性拒绝和 Plan 外部审批交接均阻止自动继续。
5. 原生重试、扩展拦截和未投递分别记录，不能只看最后一个成功回答。
6. 输入排队、插队、迟到事件、切会话、重启及下一轮模型预选不串任务或账户。
7. 完成通知与提示音去重，后台任务所有权及退出保护不出现中间释放窗口。
8. 自动输入来源与状态可持久回看；重开历史不重新执行自查。
9. 正式组件的中英文、亮暗窄窗、键盘、焦点和减少动态效果回归。
10. 真实补丁重放、钉定 RPC、Electron、Windows／macOS 云端、组合安装包和
    真实账户验收分别记录，不互相代替。
