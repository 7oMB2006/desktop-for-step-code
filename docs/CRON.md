# Cron 桌面适配

运行底座与基础管理对应仓库 Issue #134；关联及恢复 Beta 对应 #138，单任务管理对应 #142，
上游归属契约问题为 stepfun-ai/Step-Code#257。不是完整 Cron 产品交付，也不代表已发布。

## [Ⅰ] 原生状态与宿主生命周期

- Windows 与 macOS 0.6.0 使用冻结的 Step Code v0.1.5 钉点 `b5dbed938d9ae589397cf522dcf2ff89ecf4c494`；Cron 状态、管理、恢复及管理增强增量补丁由 `patches/v015/manifest.json` 引用并校验。macOS 0.6.0 已纳入同一恢复与管理增强 Beta；仍受相同信任、账户、队列和恢复授权边界约束。
- 单独的 `step-code-desktop-cron.patch` 只增加状态观察，不改任务文件 schema、调度器、归属、时间偏移或七天保护。
- Desktop 在启动环境中显式启用 `DESKTOP_CRON_STATE=1`。原生运行时通过内部状态事件发送任务 ID、单次／周期、临时／持久、下次触发和到期时间，不发送提示词或凭据。相同状态不重复发送；不为观察而额外每秒读盘。
- Electron 主进程校验快照，不把原始 JSON 转发到聊天或状态栏。保留任务的宿主不进入空闲超时和数量上限回收；任务消耗、删除或原生到期后恢复正常回收。
- 存储错误、无法解析或不支持的快照保守保留存活宿主，不能将“未知”当成“没有任务”。状态恢复后解除保护；进程已退出则清除其存活调度状态，不因旧快照永久阻塞操作。已停用进程的迟到事件不影响替代进程。
- 等待触发不等于模型正在执行。普通聊天和原生压缩仍可进行。涉及停止宿主的重启、删除历史、重定位，以及共享账户／供应商切换先检查任务；有任务时要求先删除任务，暂不隐式改变其计费方式或丢弃临时任务。
- 正常退出仍走已有的明确停止确认；退出后没有调度宿主。托盘存活不等于操作系统休眠或进程退出后仍可执行。

### 显式项目信任

- 持久任务要求上游的项目信任，Full Access 不代表项目信任。输入 `/trust` 或从指令菜单选“项目信任”，使用现有审批抽屉确认；支持稍后处理并从权限位置重新打开。
- 授权覆盖项目设置、技能、提示词、扩展及其代码执行，不只是 Cron。抽屉明确标注持久授权、目录及子目录的上游继承范围，按钮为“信任并保存”，不是“允许一次”。
- 只有用户批准后，Electron 主进程才通过管理进程调用上游 `ProjectTrustStore`，保存到 Desktop 独立 `agent/trust.json`。不调用模型，不读写个人 CLI 信任配置，不给渲染进程文件能力。
- 取消、审批超时、断开或会话失效不写入信任决定；审批后重新核对运行时与目录，目录联接被重定向时拒绝保存。原生扩展不能注入 Desktop 的信任审批标记。
- 沿用上游保存后重启生效的语义，不热加载、不自动重启其他会话。当前运行时在保存后仍不能创建持久任务；用户主动重启后才加载已信任资源。有临时定时任务时，现有宿主保护仍会阻止重启，不能通过信任操作丢弃它们。
- 桌面入口仅映射“信任当前项目”这一原生子集，暂不提供 CLI 的父目录授权、仅本次信任或撤销选项，不引入全局信任和默认信任。

### 仍需承接

有任务的宿主会保留进程资源；本阶段只保护实际有任务或状态不确定的宿主，不把所有历史会话常驻。
基础管理视图展示宿主和运行边界，支持用户主动创建和删除任务。
账户切换保护只覆盖当前存活的宿主，不等于持久任务已绑定账户；完全退出后再次打开项目的账户继承策略仍需独立确认。

## [Ⅱ] 前端管理

- 左栏“新建会话／定时任务”均分入口；管理页占主视窗，原聊天保留在后台，不为切换页面停止任务。沿用项目选择栏、展开箭头、三次方过渡与删除确认设计。
- 列表、搜索、项目筛选、详情、创建、删除、下次触发和到期时间已接入真实 bridge。创建明确选择存活宿主，显示其项目、模型、权限及账户继承关系；无宿主时不代开会话。
- 新增独立 `step-code-desktop-cron-management.patch`，只开放受环境变量保护的查询／创建／删除 RPC，复用原生 Cron 工具和调度器。主进程校验参数与数据边界，忙碌、待审批或账户／配置切换期间不能变更；管理操作不调用模型，不伪造正文或工具历史。
- 持久任务按项目与任务 ID 去重，临时任务仍按各自宿主区分。离线项目由管理进程调用上游 `CronFileStore` 只读加载，先检查 Desktop 原生项目信任；不向渲染层开放文件能力。读取失败保留旧数据并提示，未知不当成零项。
- 应用重启后，保存的持久任务可作为离线记录显示；标注“宿主离线／计划时间”，不显示为正在调度，不允许离线删除。用户需显式打开项目会话启动宿主，或使用 [Ⅲ] 的手动恢复，再管理任务。
- 创建和删除期间防重复提交，不自动重试；超时等不确定结果要求先刷新核对，避免重复创建。管理完成不等于定时任务执行完成。
- 创建默认选择持久任务；周期／单次与持久／临时分别选择，切换宿主不重置保存方式。未信任宿主选择持久时阻止提交并说明 `/trust` 审批、手动重启及已有临时任务的处理要求，不静默降级。临时选项与详情明确提示退出、更新应用或宿主终止后丢失。
- Desktop 追加的模型指引要求长期、跨重启任务优先显式 `durable: true`；信任阻塞时说明并等待，不自行改信任或降级。仅检查任务存在与否不授权重建。该指引不是执行层的意图识别或强制防线，不保证模型每次遵循；管理页的保存选项与原生信任检查仍是确定性边界。
- 这一阶段不提供独立的触发／执行结果流水；上游任务触发后仍进入实际接收它的聊天，由已有正文、审批与尾态显示真实执行结果。永久归属和运行历史留在 [Ⅲ]，不以“等待触发”冒充执行成功。

## [Ⅲ] Desktop Beta：关联会话与手动恢复

- Desktop 自有 `cron-bindings` 旁路记录关联会话，以规范化项目目录、任务 ID 和创建时间区分任务，不修改上游 `.stepcode/cron/tasks.json`。记录不包含任务正文或凭据。新建持久任务可记录管理入口或真实 `cron_create` 成功事件的会话；不从旧历史或未知任务猜测创建者。
- “关联会话 · Beta”只是桌面记录，不是上游独占所有权，也不限制其他同项目宿主接收任务。临时任务没有持久关联或复活入口。
- 离线持久任务详情提供“恢复项目调度 Beta”。选择已有、未归档且有已保存历史的同项目会话，再核对当前账户、模型、Ask 权限及本项目全部持久任务。没有候选会话时，用户需先创建并保存；不自动代开新聊天。
- 核对与取消不启动运行时、不调用模型；确认绑定两分钟有效的一次性快照。确认前重新检查项目信任、任务、会话文件、账户与模型；有变化、已过期或重放时拒绝启动，不自动重试。同项目已有存活宿主时拒绝再恢复。
- 确认后显式在选定历史启动后台宿主，先以 `DESKTOP_CRON_RECOVERY=1` 阻止原生普通触发和错过提醒的投递，校验会话 ID、模型及 Ask 后才释放调度。Ask 通过该子进程的权限环境设置，不调用会写入共享默认值的权限指令。当前查看的聊天不被强行切换。
- 恢复影响整个项目，而不是详情里那一个任务；关联更新为选定的承接会话。未释放前失败会移除门控宿主；释放 RPC 超时视为结果不确定，保留可能已开始工作的宿主，要求刷新核对，不能自动重发或杀掉任务。
- 任务加载与时间推进沿用原生规则，门控不冻结上游文件维护。错过的持久单次任务可能变成批量提醒，释放后可能调用模型并产生费用；周期任务的时间偏移、错过处理及七天到期保护不变。不重建过期任务，不保证恢复创建时的原始上下文，不保证崩溃精确一次。
- 手动恢复采用用户核对的当前账户，不宣称任务已永久绑定创建时的计费账户。受控自动恢复见 [Ⅳ]，单任务管理见 [Ⅴ]；退出后守护、休眠执行、永久无限历史及自动创建承接会话不在本次范围内。

这一层是明确标注的桌面 Beta 扩展，不视为上游原生能力；上游归属问题仍需跟进。

## [Ⅳ] Desktop Beta：受控自动恢复与记录

- 默认不自动恢复。在手动恢复的配置核对后，可明确勾选授权，作用于本项目全部持久任务与选定的已有会话，而非只作用于详情里的一个任务。最长七天，且不超过当前最早的任务到期时间；详情可关闭授权，关闭不会停止已经在线的调度宿主。
- 授权只保存规范化项目、会话 ID、账户配置摘要、模型标识、任务版本摘要和截止时间，保存在 Desktop 独立数据目录；不复制任务正文、会话文件路径或凭据。修改任务、暂停／恢复或更改账户／供应商／默认模型后不能沿用旧授权。
- 应用启动、空闲宿主异常退出时，检查同项目仍有可用且未归档的已保存会话、项目信任、账户／模型和完全一致的任务身份，再沿用 [Ⅲ] 的门控启动与 Ask 校验。当前进程已经有同项目宿主时不再创建第二个。用户正在执行、等待审批、有待发消息或活跃 Goal 中的宿主崩溃会阻断授权，不能作为空闲异常自动恢复。
- 同会话仍有待发消息时，手动恢复也会拒绝替换宿主；原断连条目及队列保留，可继续编辑或撤回，不自动迁移或发送。当前正在查看的会话恢复成功后，会显式更新连接身份并保留输入草稿与阅读位置；用户已切换到其他会话或新草稿时不抢回视图。
- 任何未暂停任务已到计划时间、周期任务已到七天截止时间，或存在未确认执行时，停止自动恢复，要求重新核对。原生周期任务错过触发后的时间推进也不被当成自动付费补跑的许可。执行结果未知可在核对后单独确认，但历史仍标为未知，不改写为成功。
- 每次自动尝试先将授权置为阻断，只有确定恢复成功才重新启用。失败、不确定释放或快照不符不自动重试；撤销或另一次阻断不能被迟到的成功结果覆盖。仍不创建新会话、重建过期任务、替换不可用账户／模型、切到直调 API 或提升至完全访问。
- 自动启动将授权、任务到期与最早触发时间的最小值传给原生门控；运行时在同步释放门控前重新检查时钟与错过触发，初始化期间跨过截止时间也拒绝自动释放。旧运行时缺少 `desktop-cron-recovery-guard` 能力时拒绝自动恢复。损坏的单项目授权保持原样并记录错误，不阻断其他健康项目的检查。
- `cron-history` 按项目原子保存最多 200 条有限流水，界面提供最近 30 条的默认折叠入口，任务消耗后仍可从项目记录查看。仅记录时间、任务身份、会话和状态，不保存指令、工具输出或凭据。区分触发、执行、等待、失败、中断、未确认与恢复状态；只有本次实际收到助手输出且获得权威成功收尾才标为“本轮已完成”，不保证任务内容正确。崩溃遗留的活动记录重开后为未确认。
- 历史轮转不会清除未确认阻断：被挤出的未确认记录以同文件原子保存的标记保留，只在用户明确确认后解除。兼容读取旧数组格式，下次写入迁移为版本化记录；不将未知结果改写为成功。
- 这不是新守护进程或永久会话所有权。文件锁继续由上游调度器负责，不能保证 Desktop 与外部 CLI、多台机器之间独占调度，也不承诺崩溃精确一次。用户手动打开其他同项目会话仍走原生账户继承与共享任务行为，不属于本授权自动恢复保证。
- 详情“当前调度宿主”旁提供“前往宿主会话”图标，复用已有聊天切换与阅读状态。主进程按当前运行时身份校验，只切换在线宿主；离线入口禁用，迟到点击失败也不退回加载历史或启动新运行时。该入口不以关联会话代替实际宿主，不触发恢复或调用模型。

## [Ⅴ] Desktop Beta：单任务暂停、恢复与编辑

- 详情提供单任务暂停／恢复和编辑指令／五字段本地时间表达式。只操作明确选中的在线宿主内的任务，不停掉整个宿主，不影响其他任务；离线记录需先启动或核对恢复宿主，暂不支持离线写入。
- 取消编辑不保存修改；下次打开从任务当前已保存的时间与指令重新初始化，保留原有展开／收起动画。
- 管理通过环境保护的 `desktop_cron` 更新动作执行，不向模型增加新的工具。持有 Desktop 宿主变更锁，并由原生文件锁合并项目最新记录；基于任务内容与暂停状态的版本检查防止旧页面覆盖，正常 `nextFireAt` 推进不使编辑失效。
- 编辑、暂停或恢复的 RPC 发出前，先持久阻断本项目旧自动恢复授权，再重新校验宿主身份；授权写入失败不发更新。暂停后恢复或编辑后改回原文均不能使旧授权复活，需重新核对授权。这不承诺检测外部 CLI 的全部往返修改。
- 保留任务 ID、创建时间、关联、单次／周期、临时／持久及原截止时间，不删除重建，不刷新七天保护。仅改指令保留下次计划；改时间或恢复从新的下一个匹配时间开始，并保留原生偏移。暂停期间不投递，恢复不补跑；到期暂停任务直接移除，不做最后一次执行。
- **暂停持久记录使用 Desktop Beta `schemaVersion: 2` 与 `desktopPausedAt`。** 只有启用 `DESKTOP_CRON_STATE=1` 的新版 Windows Desktop 运行时可识别。原生／旧版 schema-1 读取器会忽略并保留未知记录，不能调度或恢复它们；不要将旧版列表的“没有任务”误当成记录已删除。若要转回旧版或 CLI 管理，应先在新版 Desktop 显式恢复或删除这些记录。恢复会还原 schema 1。
- 这是明确修改共享任务兼容格式的新增 Beta 补丁 `step-code-desktop-cron-enhancements.patch`，不是原先只观察状态的补丁，也不是已合入上游的暂停／编辑接口。临时任务的暂停仍只在内存，退出后照常丢失；操作失败或结果不确定先刷新核对，不自动重发。
