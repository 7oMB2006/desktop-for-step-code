# 桌面通知与声音

设置入口：设置 → 通用 → 通知与声音。

| 选项 | 默认 | 行为 |
| --- | --- | --- |
| 审批请求通知 | 开启 | 后台会话出现仍有效的交互确认时发送系统通知 |
| 任务完成通知 | 关闭 | 后台会话收到权威的本轮成功完成事件时发送系统通知 |
| 完成提示音 | 关闭 | 成功完成时播放一次现有提示音，前后台均生效 |

三项独立保存到 Desktop 档案的 `preferences.json`；只接受布尔值，
旧档案缺少字段时使用上述默认值。保存失败保留原通知设置并使用现有错误反馈。
通知设置立即生效，不重启运行时，也不修改 Step Code 或 Windows 设置。

## 行为边界

- 使用 Electron 主进程的原生 `Notification`，Windows 展示与通知中心由系统管理。
  所有原生通知均为静音，声音只由“完成提示音”控制。
- 选中的来源会话已在可见、未最小化且有焦点的主窗口或 MiniChat 中时，不发系统通知。
  窗口在后台、最小化、隐藏到托盘，或正在查看另一个会话时，可以发送。
- 点击只恢复主窗口、打开来源会话并展开它的待审批界面，不提交任何批准回复。
  使用现有导航和共享草稿机制，不把另一会话的审批带入当前会话。
- 只有主窗口处理完成音频，MiniChat 不重复播放。关闭声音不关闭任务完成动画。
- 停止、失败、崩溃、普通信息事件、历史恢复和中间自检事件不作为成功完成。
  复用现有 `desktop_task_completed` 判定，不新增模型请求或运行时补丁。
- 通知只含通用中英文文案，不含项目路径、命令、问题或回复正文。
- 审批解决或过期、相应开关关闭、来源会话进入前台时撤回失效通知；
  来源会话开始下一轮工作时撤回旧完成通知，包括 worker 已回收再启动的情况。
  系统横幅超时后保留通知中心的点击路由；最多保留 32 个原生通知对象。
- 系统不支持通知或通知发送失败不能打断任务。尊重 Windows 勿扰模式、
  应用通知权限和横幅设置，不绕过或修改它们。

## 验证

单元测试：`Desktop/tests/desktop-notifications.test.ts`、
`completion-sound.test.ts`、`session-runtimes.test.ts`。

`Desktop/scripts/verify-notifications.mjs` 通过真实主进程、preload、渲染器和
暂存运行时，使用独立临时档案与本地 HTTP 模型 fixture 验收。
原生通知的显示/关闭及焦点在此脚本中受控替换，以确定性验证路由，
不打扰日用应用或真实审批。脚本已加入共享 CI 的 interface 组，
支持既有的 `DESKTOP_VERIFY_EXE` 包验收入口。

可选 `--native-smoke` 仅检查系统发出 `show` 确认，不证明横幅可见或真实鼠标点击。
系统横幅、通知中心物理点击、安装身份及 macOS 原生行为仍需对应环境人工验收。
实际本地结果见 [验收记录](VERIFICATION.md)，不是公开发布或云端 CI 通过声明。
