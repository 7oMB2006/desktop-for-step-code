## 1. 目标与范围

让第三方作者提供标准文件，即可复用 DFSC 的插件卡片、文档、教程、
归属信息和基础配置界面；BVR 是完整参考实现，而不是所有插件必须照搬的业务模型。

用户在计划审查后授权以 goal 推进 [Ⅰ] 至 [Ⅴ] 实现。
最初实施范围不含打包、提交、推送、发布或修改桌面快捷方式；
之后经分别授权进入 PR #195 和 Windows 打包验收，并按工程约束更新快捷方式。
公开发布及市场投稿仍不包含在本轮收尾范围内。
展示协议和配置协议分层交付，不宣称完整第三方前端 SDK。
交付顺序保持为：完成骨架并共同定稿，再以普通第三方作者的约束
制作一个独立示范插件，演示投稿和上架后的真实体验。

统一的内容：

- 页面布局、页签、图标尺寸、主题、展开动画、聚焦、滚动和草稿生命周期。
- 元数据格式、文档读取、教程外链、作者归属、配置字段和错误状态。
- 文件与网络边界、配置修订检查、凭据写入规则和验收标准。

不强制统一的内容：

- README 的章节与措辞、教程数量、业务字段和模型连接数量。
- ASR、模型、API Key、运行目录和 Cookie；不需要就不声明、不显示。
- 非 MCP 插件不伪造服务开关，也不因缺少专用表单而冒充配置成功。

## 3. 数据与责任边界

### 3.1 原生清单仍然权威

`step.plugin.json` 继续定义插件 ID、名称、版本、资源声明、仓库和现有图标。
可选的 `dfsc.plugin.json` 只补充 Desktop 展示信息，不覆盖原生身份或运行行为。
有冲突时显示受限警告，不能用展示清单把另一仓库、作者或版本替换成已验证来源。

新增展示清单以 `schemaVersion: 1` 开始。建议形状：

```json
{
  "schemaVersion": 1,
  "authors": [{ "name": "Original project contributors" }],
  "maintainers": [{ "name": "Desktop package maintainer" }],
  "license": "MIT",
  "documentation": {
    "readme": "docs/DFSC.md",
    "changelog": "CHANGELOG.md"
  },
  "tutorials": [{
    "title": "Getting started",
    "url": "https://example.com/tutorial",
    "creator": "Demo creator",
    "kind": "community"
  }],
  "links": [{
    "kind": "issues",
    "title": "Report an issue",
    "url": "https://github.com/example/plugin/issues"
  }]
}
```

该示例只说明字段，不是可以原样发布的真实教程。
实际 schema 在 `docs/plugin-schemas/`，可安装样例在 `examples/plugins/`。
未写清单时保留现有安装与运行行为，优先尝试已安装包内的 `README.md`。
未指定或不存在的更新记录不生成页签。无文档时展示简介，不假称已读取 README。
不自动删除 README 的标题或重写作者原文；桌面专用说明由作者显式选择文件。
宿主界面支持中英文；可选 `locales.zh/en` 选择作者提供的简介和同包文档，
缺少翻译时保留原文，不承诺自动翻译。作者明确声明的 `links` 展示为入口卡片，
正文链接不自动提取；具体格式见作者指南和 schema。

署名分为原项目作者、Desktop 封装/适配维护者和教程创作者，均属于声明性信息，
不是 DFSC 的身份认证、官方背书或可信代码标记。教程平台名从实际 URL 主机映射，
作者不能写一个“哔哩哔哩”标签掩盖另一个目标网站。

### 3.2 宿主查询数据与作者数据分离

Star 不进入作者清单，也不与作者署名一起充当安装信任依据。
由主进程依据原生清单中规范化的 GitHub 仓库地址查询，记录 `count`、
`checkedAt` 和查询状态；卡片与详情使用同一缓存。未知不是零。
当前 fixture 的手工 Star 和文档映射必须在真实接入后退出正式数据路径。

### 3.3 文档与配置使用稳定包身份

详情读取不能只依赖显示名或可碰撞的插件 ID，也不能把当前市场中的匹配副本冒充原始安装来源。
宿主在 Desktop 私有目录持久化安装记录，至少绑定安装实例 ID、来源标识、
市场包名、原生插件 ID、安装目录归属、锁定提交或内容指纹及记录版本。
来源记录表示安装出处，不证明作者身份或代码可信；不能由包内清单自行声明。
移除市场不抹去已安装包的来源记录，同名市场换源不继承原绑定。

区分两种身份：

- 稳定安装/配置身份：宿主分配并持久化，正常同源升级不因版本变化丢失配置；
  换源、fork、卸载后重装不得仅凭名称或原生 ID 自动继承秘密，另行确认迁移。
- 临时包引用：宿主签发，绑定稳定身份或发现来源、市场包名、原生 ID、
  已安装/发现状态及包修订或内容指纹，只用于读取该快照的受限资源。

已安装详情读已安装副本；发现详情读该市场的锁定副本，不混用不同版本。
安装、卸载或市场更新后拒绝过期引用，并使相关文档缓存失效。
临时引用注册表归 Electron 主进程中的持续服务所有；当前 capability 管理子进程
每次请求后即退出，不能把跨请求引用只保存在该子进程的内存中。
应用重启后重新签发临时引用，稳定安装记录保留。
渲染进程不能提供任意绝对路径、仓库根目录或文件写入目标。

安装副本与记录的写入须有可恢复的一致性流程：以待完成记录标注操作，
校验安装结果后提交；中断或部分失败在下次读取时核对并修复或报告，
未核实副本不得获得配置/秘密绑定。卸载失败不提前删除来源记录。
旧安装没有记录时标为“来源未确认”，允许查看已安装副本的文档；
与当前市场副本逐文件一致时可以显示“匹配市场”及全部候选，但不生成安装记录或授予配置权限。
不能把它自动归给当前同名市场，也不能自动重绑既有 BVR 配置或账户授权。
来源认领与配置迁移须另经明确确认并核对实际包身份。

### 3.4 原生运行时 ID 冲突与市场遮蔽

不升级 runtime pin，不承诺同一原生插件 ID 可安装多个来源的副本。
安装前读取并校验目标 `step.plugin.json` 的实际 ID，检查已安装目录，
拒绝重复原生 ID 和目录名冲突；检查不能只把市场包名与已安装 ID 比较。
冲突检查与安装/卸载串行化，操作前重新核对所选包修订。

当前原生市场枚举会按包名去重，已安装枚举会按插件 ID 去重。
宿主须对受限目录的原始清单检查冲突与同名遮蔽，不能因原生列表隐藏了另一项
就报告“没有冲突”，也不承诺所有同名市场项都能正常安装。
发现遮蔽时提供明确警告和可识别的来源；含糊的安装动作不可执行。
已有重复 ID 目录时保留文件、提示冲突，禁止含糊的卸载/配置/秘密绑定操作，
不擅自删除或迁移其中任何一份。文档隔离不能替代运行时冲突处理。

## 4. 实施顺序

### [Ⅰ] 展示协议与真实数据通路

交付：

- 新增展示清单 schema、主进程验证器和有效/无效测试样本。
- 版本 1 固定白名单字段；未知主版本不解释其新能力，保留原生插件可用。
- 清单上限 64 KiB，作者/维护者各不超过 8 项，教程/链接各不超过 8 项；
  名称、标题、URL 等分别设定长度上限，超限项不能无限进入 IPC。
- 目录列表仅返回有界的基础元数据和文档存在性，不携带整份 README、图片或配置秘密。
- 详情通过窄 typed preload/IPC 按需读取；切换目标后丢弃迟到结果。
- 增加宿主持久化安装记录、旧安装“来源未确认”迁移和主进程临时引用管理。
- 安装前校验实际原生 ID，串行处理冲突检查与变更；检测原生枚举隐藏的同名项
  和已有重复 ID，不通过扩大 runtime 能力绕过冲突。
- 更新 `capabilities.ts`、桥接契约和现有目录适配，正式页面不依赖测试映射。

验收门槛：

- 两个 ID 相同但来源不同的候选包、已安装旧版与市场新版均不能串文档；
  同 ID 副本不能同时安装，不能把“读取隔离”当成“允许运行时共存”。
- 重启、移除市场、同名市场换源后安装来源不漂移；旧安装不自动认领来源或秘密。
- 不同市场包名却声明同一原生 ID、同名市场遮蔽、既有冲突目录均有负向测试；
  并发安装、安装中断和卸载失败不留下被误认成完整安装的记录。
- 缺清单、坏 JSON、未知版本、超限文件只影响展示扩展，不破坏原生资源加载。
- 读取失败保留返回和重试；警告不得包含绝对私密路径、凭据或原始环境变量。

### [Ⅱ] 随包文档、教程与通用详情

交付：

- 保留“卡片主体看说明、小齿轮进配置”；使用说明、配置、能力依实际内容展示，
  更新记录仅在有效文件存在时出现，所有隐藏页签都有明确默认回退。
- 配置草稿、脏状态和焦点不因阅读说明丢失，阅读文档不自动重启或调用模型。
- 文档正文单文件上限 256 KiB；选中详情后读取，不随目录轮询重复解析。
- 仅允许包内相对路径，明确拒绝目录穿越、绝对路径、盘符、UNC、ADS、
  符号链接和 junction 越界；读取前后核对归属与实际文件身份。
- Markdown 禁止执行 HTML、脚本、iframe；外部链接只接受无凭据 HTTPS，
  以显式用户点击打开。不嵌入远程播放器，不自动抓取外部封面或图片。
- 包内 PNG/JPEG/WebP 图片经宿主校验后按资源引用提供，不暴露磁盘路径。
  每张不超过 1 MiB、边长不超过 4096、每份文档最多 8 张且总计不超过 4 MiB。
  图标沿用现有 PNG 规则，不能把图标的小尺寸限制直接套给文档截图。
- 支持同页锚点；相对 Markdown 链接只能在同包的受限文档范围内按需导航，
  具有返回行为。其他相对目标不转成 `file://` 或任意浏览器导航。
- 教程、外链和更新记录缺失时自然省略，不留空卡片、失效按钮或固定 BVR 文案。

验收门槛：

- 文档/资源切换时的过期包引用、恶意路径和读取竞态均有负向测试。
- 缺失、过大或损坏图片有替代文本，远程图像不会产生请求。
- 深浅主题、390/640/900/1440px、长标题、长 URL、代码块和宽表格无页面溢出。
- 键盘、焦点边框、共享三次方动效与 reduced-motion 符合 `DESIGN.md`。

### [Ⅲ] 宿主 GitHub Star 查询

交付：

- 首版由明确的“刷新仓库信息”操作触发，目录加载只读缓存，不为渲染文档联网。
- 网络操作仅在主进程；只请求 GitHub API 的固定仓库查询路径，
  不接受作者提供的 API 地址，不跟随到任意域名，不携带 Step Plan/API 凭据。
- 超时 5 秒、响应体上限 256 KiB、并发最多 2 个，同仓库去重。
- 缓存 6 小时内不重复查询，手动刷新同仓库仍有最少 1 分钟冷却；
  缓存与当前包来源分开，以规范化仓库为键。用户可正常离线使用其余页面。
- 处理限流、断网、无仓库、仓库迁移或删除，保留并标明旧快照时间。
- 只显示 Star 数及时间，不暗示点击即可给 GitHub 加星。

验收门槛：

- 正常零星、未知、负数/非整数响应、限流、超时、重定向、旧数据均覆盖。
- 失败不会把最后一次快照改成零，也不阻塞安装、文档或配置。
- 请求使用 mock 验证，另记一次明确的真实公开仓库查询，不相互替代。

### [Ⅳ] 声明式基础配置协议

此阶段依赖 [Ⅰ][Ⅱ] 的身份和文档边界。
已选定 `json-file-v1`，通过实际安装的无网络 stdio 便笺 MCP 验证消费通道。
原生清单显式非秘密 sentinel 阻止 Step 凭据自动注入；读取器从自己的安装位置
核对出处、包/schema 指纹、内容哈希与不可变配置 revision。
不因完成该协议就宣称“所有插件已有设置前端”，不泛化 BVR 账户桥。

交付：

- 独立的版本化配置 schema，支持有限的 text/number/enum/boolean/secret/path 字段，
  静态分组、帮助文案、必填、数值范围和有限长度；不支持 JS 表达式或动态代码。
- 模型连接是可选的具名分组，可以零组、一组或多组；ASR 只是 BVR 声明的角色。
  第一版分组、字段和选项均设定数量上限，字段类型变化不得隐式转换秘密。
- UI 使用现有宿主组件、统一焦点和错误映射，不允许作者注入 CSS、HTML 或 React bundle。
- schema 不能声明任意落盘路径、执行命令、环境变量写入或宿主账户权限。
- 主进程按持久化安装记录绑定的稳定配置身份存储公开值与秘密，
  不按市场显示名、可碰撞原生 ID 或每版变化的临时引用单独命名；
  read 返回 revision/公开值/hasKey，
  write 只接收新秘密与明确的保留/替换/删除意图；保存后清空新秘密输入。
- 原子保存并比较配置 revision。密钥不进入作者清单、普通目录投影、日志或模板。
- 每种配置进入 MCP/工具进程的消费规则必须有显式允许的宿主适配和测试。
  没有消费者的字段不得显示“配置已生效”或凭空注入进程。
- 安装、已保存、待重启、已连接和业务请求成功是不同状态；
  保存不自动重启、不在后台切计费、不在检查环境时试用付费模型。

验收门槛：

- 至少验证零连接、一组连接、多组连接三个插件，证明没有强制主力/ASR。
- 密钥保留、替换、删除、冲突、失败、卸载/重装和包版本变更均有既定行为。
- 配置只绑定已确认的稳定身份，不能因市场显示名、fork 改名或重新安装
  读取另一来源的秘密；来源未确认或存在运行时 ID 冲突时阻止含糊绑定。
- 跟随 DFSC 的模式默认不属于通用 schema。BVR 保留现有显式桥和授权。
  未经支持/授权的插件不能通过自报能力取得账户、模型代理或 Key。

### [Ⅴ] 示例、市场同步与可复制验收

交付：

- `resource-starter`：无 MCP、无 Key 的最小示例，加上真实可读的展示清单、
  README、截图和可选更新记录；不填虚假仓库、Star 或作者。
- 增加基础配置示例，展示 [Ⅳ] 的已实现字段和真实消费方式；
  未实现前保持现有 `host-adapter` 被清楚标为宿主贡献模板。
- BVR：保留真实仓库、教程与许可证，替换 fixture 中的示例署名和更新记录，
  以随包真实文档作为完整参考。BVR 业务配置与特权账户桥不伪装成通用功能。
- 社区市场同步规则必须复制并哈希锁定展示清单、文档和引用图片；
