# DFSC 插件开发与界面约定

这是当前插件骨架分支的开发说明，不代表已发布安装包都支持这些扩展。
资源、说明和受限的声明式设置可以由作者提供；它不是第三方前端执行 SDK。

## 交付层次

| 层次 | 由谁维护 | 当前支持 |
| --- | --- | --- |
| 可安装资源 | 插件自己的仓库 | `step.plugin.json`、技能、提示命令、MCP 声明和许可证 |
| 标准说明 | 插件自己的仓库 | 可选 `dfsc.plugin.json`、包内 Markdown、PNG/JPEG/WebP、教程与署名 |
| 基础配置 | 插件自己的仓库 | 可选 `dfsc.settings.json` 与 `json-file-v1` 原生 stdio 消费者 |
| 特殊宿主适配 | DFSC 宿主 | BVR 账户桥、StepPage 准备等，不是可自报的通用能力 |

没有第三方 HTML、iframe、React bundle 或 JavaScript 入口加载器。
给清单添加 `frontend`、`entry` 或 `provision`，不会自动获得界面或安装能力。
没有受支持的配置消费者时，详情保留已有 MCP 技术设置入口。
BVR 的账户桥也不是可按插件名称自动继承的通用能力。

## 固定布局

```text
插件
  已安装 / 发现 / 市场来源                          搜索、刷新
  插件卡片：图标、名称、版本、简介、来源
            服务开关                     GitHub、设置齿轮

  二级详情
    返回全部插件 / 当前名称
    插件标识、版本、来源、简介          GitHub、服务开关、卸载
    使用说明 / 配置 / 能力             更新记录按有效文件出现
    可滚动正文
    保存状态                           保存配置、重启当前会话
```

- 列表和详情是两个层级，不做左右分栏，也不另造小型配置弹窗。
- 卡片只保留必要信息；GitHub 在外层可直接访问，设置只用小齿轮。
- 服务开关不加 tooltip，但保留可访问名称。无 MCP 的插件禁用该开关。
- 开关控制该插件的 MCP 服务，不代表卸载技能、命令或即时断开已有连接。
- 详情复用宿主的返回、页签、滚动和底部操作区，插件表单不再套一层页面壳。
- 当前「能力」展示已发现的 MCP 和技能；命令可以被运行时加载，不等于这里已有命令列表。
- 「使用说明」按需读取安装副本；发现页读取市场副本，不执行 Markdown 中的 HTML。

实现参考：`Desktop/src/PluginCenter.tsx`、`Desktop/src/plugin-center.css`。

统一的是页面壳、控件和状态语言，不是所有插件的业务字段。
纯技能插件不需要模型设置；远程 MCP 不一定需要本体目录；
没有语音能力就不出现 ASR 分组。不要为了套 BVR 的外观制造无效设置。
需要复杂业务界面但当前宿主未支持时，应明确其需要后续适配，不放假按钮。

## BVR 表单对应关系

| 顺序 | 页面内容 | 真正含义 |
| --- | --- | --- |
| 1 | 模型来源 | 跟随实际调用的 DFSC 会话，或使用 BVR 独立连接 |
| 2 | 主力模型 | 独立模式的视频理解、内容整理连接 |
| 3 | 语音识别 ASR | 独立地址、Key、专用模型，不借用主力配置 |
| 4 | 调用前确认 | 跟随模式首次付费请求的原生授权，不是保存配置时授权 |
| 5 | 本机运行环境 | BVR 本体路径、Node 与依赖检查，不是下载安装器 |
| 6 | 下载与高级设置 | 临时目录、Cookie 文件、下载代理、优先字幕 |
| 7 | 固定底栏 | 保存配置与手动重启；保存本身不停止会话或 Cron |

详情的「配置」回答如何准备；「能力」回答声明了什么、当前会话是否连上；
「说明」回答身份与配置范围。不要把三者混成一个长表单。

实际字段层参考 `Desktop/src/BvrConfigurationForm.tsx`。
配置边界与计费语义见 [BVR 宿主桥](BVR_HOST_BRIDGE.md)。

## 控件与视觉语言

| 内容 | 固定用法 |
| --- | --- |
| 互斥模式 | 分段按钮，选中状态明确；不把切换模式写成立即授权 |
| 接口地址、模型 | 有标签的直接输入，非自然语言配置或要求用户手写 JSON |
| API Key | 密码输入、显隐按钮；仅输入的新值可显隐，已保存值不返回渲染进程 |
| 文件与目录 | 路径输入 + 文件夹按钮，调用宿主原生选择器 |
| 二选一设置 | checkbox 或 switch，不用普通文字按钮模拟 |
| 参数集合 | 项目已有选择器，不新造浏览器风格不一致的菜单 |
| 次要设置 | `CapabilityDisclosure`，使用共享箭头、三次方展开/收回与 reduced motion |
| 主题 | `--bg`、`--surface`、`--ink`、`--muted`、`--border`、`--primary`，不固定浅色背景 |
| 图标 | Lucide 工具图标；插件标识使用有归属的本地 PNG，不抓取远程图标 |
| 布局 | 正文分区不套卡片，主力与 ASR 独立分组，窄屏自然改为单列 |
| 聚焦 | 复用共享焦点样式；滚动与裁切容器内预留至少 4px，四边和圆角完整可见 |

图标文件当前须位于插件目录内，为不超过 128 KiB、宽高各不超过 512 的 PNG。
省略图标时使用宿主缺省图标。GitHub 元数据只展示无凭据的 HTTPS 仓库地址。
统一使用固定字号，间距、强调色和动效遵循 [DESIGN.md](../DESIGN.md)。

## 状态与文案

不要用一个「正常」同时表示安装、配置、连接和计费成功。

| 状态 | 建议文案 | 不应暗示 |
| --- | --- | --- |
| 资源安装成功 | 已安装 | 本体依赖已经安装、服务已经连接 |
| 服务开关开启 | 服务已启用 | 当前会话已重新加载 |
| 配置草稿变化 | 有未保存的更改 | 磁盘或计费方式已经变化 |
| 保存成功 | 已保存，现有会话需重启后应用 | 已自动重启所有会话 |
| 环境检查成功 | 运行目录与依赖就绪；未验证账户或调用模型 | Key 有效、额度充足、真实请求成功 |
| 连接成功 | 已连接 · N 个工具 | 工具业务已端到端验收 |
| 未查询连接 | 当前会话连接状态未确认 | 断开或成功 |
| 已保存 Key | 已配置，留空保留；输入新值替换 | 星号字符串是可读取的真实 Key |
| 保存冲突 | 配置已变化，请重新读取后再保存 | 静默覆盖另一个页面的新配置 |

错误放在相关表单内，保留草稿和重试入口。离开脏表单先确认；
在主视图间切换不丢草稿。加载、保存和检查期间禁止重复提交。
错误和检查结果不得包含 Key、Cookie 内容、连接令牌或原始环境变量。

跟随账户模式必须说明实际调用会话、地区、渠道、模型和额度成本。
独立模式必须说明其计费不随 DFSC 聊天账户切换。禁止静默 Plan → API 回退。
这些是 BVR 已实现的语义；其他插件需独立实现和验证，不能仅复制文案宣称支持。

## 示例骨架

见 [examples/plugins](../examples/plugins/README.md)：

- `resource-starter/`：可安装的本地市场，包含技能与 `/dfsc-example`，不运行外部服务。
- `config-starter/`：可安装的本地便笺 MCP，设置真实影响工具输出，无外部账户或付费接口。
- `host-adapter/ConfigurationFields.tsx`：宿主字段层骨架，复用实际控件与样式，主力和 ASR 分开。
- `host-adapter/README.md`：接入责任、桥接契约、草稿与保存约束。

独立投稿流程示范见
[文本整理台](../examples/community/text-workbench/README.md)：
只使用上述公开协议，有实际离线工具、声明式设置、指令、技能、
作者说明、原创图标、测试与真实安装截图。它不是 BVR 或宿主字段模板，
尚未公开投稿；本地文件锁不替代远程 Git 提交和社区同步锁。

字段骨架不是插件可上传的前端文件。接入时还需要契约、preload、主进程校验、
私密存储、错误映射、宿主路由以及验证；不要给渲染进程 Node 或文件系统权限。

## 标准展示文件

原生 `step.plugin.json` 的身份、版本和资源声明仍然权威。
在同目录添加可选的 `dfsc.plugin.json`：

```json
{
  "schemaVersion": 1,
  "authors": [{ "name": "Your project contributors" }],
  "maintainers": [{ "name": "Your package maintainer" }],
  "license": "MIT",
  "documentation": { "readme": "README.md", "changelog": "CHANGELOG.md" },
  "tutorials": [],
  "links": []
}
```

编辑器校验使用 [展示 JSON Schema](plugin-schemas/dfsc.plugin.schema.json)；
设置对应 [配置 JSON Schema](plugin-schemas/dfsc.settings.schema.json)，均为 draft-07。
JSON Schema 检查文件结构；宿主还校验实际路径、数量总限、重复 ID、默认值、
消费服务和安装出处，不能用编辑器校验替代安装验收。

作者、封装维护者和教程创作者分开署名，内容为作者声明，不是身份认证。
教程项使用 `title`、`creator`、`url`、`kind: "author" | "community"`；
平台由宿主从 URL 识别。不要伪造视频、仓库或 Star。
`links` 用于作者明确推荐访问的展示网站、项目文档等入口，填写 `title` 和 `url`；
宿主在使用说明顶部、视频教程之后显示独立的可点击卡片，包含标题、目标域名和外跳箭头。
正文里的 Markdown 链接保持普通链接，不自动提取为卡片，也不抓取网页封面或摘要。
没有文件就不声明对应文档，没有扩展文件仍可显示包内 `README.md`。
不自动删标题或重写作者正文；需要专属桌面说明时显式指定 `docs/DFSC.md`。

清单上限 64 KiB，作者/维护者各 8 项，教程/外链各 8 项。
Markdown 每份 256 KiB；相对 Markdown 链接在同包内导航并支持返回。
只显示包内 PNG/JPEG/WebP，每张 1 MiB、4096px 边长，每页最多 8 张、合计 4 MiB。
不加载远程图片、播放器、HTML、SVG 或脚本，不支持 `file://`、目录穿越或 junction 越界。
教程及外链仅接受无凭据 HTTPS，用户点击后外部打开。
打开插件中心后，宿主异步查询已展示插件的公开 GitHub 星标，最多同时查询两个仓库，
使用六小时缓存及失败冷却；不阻塞目录展示，也不调用模型。作者清单不能填写计数。
查询中显示省略号，失败或限流显示未知状态，不伪造为零；有旧快照则保留并标注时间。

### 语言与来源

界面标签跟随 Desktop 语言。作者可以为简介和说明文件提供语言版本：

```json
{
  "schemaVersion": 1,
  "documentation": { "readme": "README.md" },
  "locales": {
    "zh": {
      "description": "插件的中文简介。",
      "documentation": { "readme": "README.zh-CN.md" }
    },
    "en": { "description": "An English description of the plugin." }
  }
}
```

未提供的翻译回退原始声明，文档仍只从同包读取；不在线翻译或改写作者正文。
宿主为既有随包简介提供精确文本的兼容译文，不按第三方插件 ID 强行覆盖。

来源独立于安装状态：有有效安装凭据时显示实际市场名；旧安装与市场副本逐文件一致时，
显示「匹配市场」及市场名，不冒充有安装凭据，也不由此授予声明式配置权限。
多个一致副本保留所有候选；无法确认或存在冲突时直接标注，不一律写成「本机安装」。
移除市场后，有效安装凭据仍保留原市场信息。

## 声明式基础设置

完整可安装样例见 `examples/plugins/config-starter`。只声明用到的字段，
可以没有连接、一组连接或多组独立连接，不要求所有插件都有模型/ASR。
字段类型限于 `text`、`number`、`enum`、`boolean`、`secret`、`path`。
分组最多 8 个，每组最多 16 字段、总计 64 个；枚举最多 32 项。
字段采用固定 ID、标签、可选帮助、必填、默认值及长度/数值范围。
`path` 使用 `selection: "file" | "directory"`，默认目录；
文件选择通过宿主原生对话框，选择路径不授予渲染进程文件访问权限。
不能声明命令、任意写入路径、环境变量目标、CSS 或宿主账户权限。

消费协议首版是 `json-file-v1`，绑定一个已经在原生清单声明的 stdio MCP：

```json
{
  "schemaVersion": 1,
  "consumer": { "kind": "json-file-v1", "server": "notes" },
  "groups": [{
    "id": "format",
    "title": "Note formatting",
    "fields": [{ "id": "prefix", "label": "Prefix", "type": "text", "default": "Note: " }]
  }]
}
```

对应原生服务必须显式声明非秘密 sentinel：
`"env": { "STEPFUN_API_KEY": "DFSC_INDEPENDENT_PLUGIN" }`。
它阻止上游自动注入已登录 Step 凭据，不是可调用模型的 Key。
使用示例里的独立读取器，并在启动时清除继承的提供商凭据。
声明 schema 并不能让不读取该协议的旧 MCP 自动使用新设置。
全局 MCP transport 覆盖了该原生服务时，宿主会拒绝含糊的配置绑定。
安装不执行依赖安装；示例的 `node` 要求本机 PATH 上已有 Node.js。

宿主在 Desktop 私有目录维护来源记录、稳定安装实例与配置修订，
不在插件包里写 locator 或 Key。渲染进程只收到公开值、revision 和秘密存在性；
秘密写入明确区分保留、替换、删除，保存后清空新秘密输入。
每次保存生成不可变 revision 快照，以原子 binding 指针和内容哈希提交；
中断保存不会把未提交快照视为有效设置。同 revision 下改写公开值或秘密会被拒绝。
读取器从自己的安装位置推导 profile，不使用 HOME 或个人 Step Code 作为后备，
每次工具调用重新核对实例、包内容、schema、绑定和配置 revision。
变更或撤销后旧进程拒绝新业务；用户需要明确重启。
这是同一 OS 用户下的原生代码协议，不是恶意插件沙箱：
秘密对界面不可回读，不等于对获准消费它的原生插件不可读。

来源未知的旧安装不会自动认领当前同名市场或继承配置。
重复运行时 ID 不允许共存；不同市场的同名包会提示冲突，不静默选择一个。
卸载撤销配置绑定，私有历史配置保留；重装使用新实例，不自动接走旧秘密。
schema 变化不自动转换已有秘密。BVR 的旧专用配置仍由 BVR 适配维护，
不能把这些规则当成已经完成 BVR 配置迁移或账户桥泛化。
安装中断或卸载失败会保留未完成记录并提示；不会自动认领为完整安装。
当前不提供旧配置认领、schema 迁移或同源自动升级界面，需要另行设计确认流程。

旧 DFSC 会忽略新增展示文件；新 DFSC 仍允许缺少这些文件的旧资源插件。
仅声明 `dfsc.settings.json` 不会让旧版宿主获得配置界面；
作者必须写明所需 DFSC 版本和消费者依赖。首版没有自动安装依赖、
自动更新、第三方前端执行或通用宿主账户授权。

## 投稿与验收

插件先在自己的仓库提交资源，再向 `7oMB2006/dfsc-community-plugins` 提收录 PR。
登记上游仓库、完整 40 位提交 SHA、资源路径、许可证与维护者说明。
市场维护者通过同步工具生成资源副本、锁定哈希与原生市场清单；
展示清单、设置清单、README、引用的文档和图片、消费者文件都必须被复制并锁定，
从实际安装副本验证，不只检查作者仓库的文件是否存在。
仅填写项目 GitHub 地址不等于存在可安装资源。
社区同步会用维护者的 `docs/plugins/<id>.md` 替换资源根 README；
需要保留作者专用说明时，把原文放在包内 `docs/`，
并在展示清单中显式指定该文件。不要声明并不存在的更新记录或截图。

不要提交依赖目录、真实 `.env`、Cookie、profile、会话、日志或本机绝对路径。
市场更新不等于已安装插件升级；不要承诺当前没有实现的自动更新。
保持插件原许可证与素材归属，完整流程以社区市场 `CONTRIBUTING.md` 为准。

插件与配置的最小验收包括：

- 明暗主题、1440/640/390 宽度、长路径、滚动后的首末字段和完整焦点边框。
- 草稿保留、取消离开、重复操作保护、失败重试、并发配置冲突、Key 不回读。
- 原生市场发现/安装、技能与命令加载、服务开关、重启、卸载后配置保留。
- 本地检查、真实 MCP 连接、模型请求和真实账户计费分别记录，不互相替代。

独立示范已按普通投稿者条件完成本地安装与工具验收，不借用 BVR 特权，
也没有按示例名称增加宿主例外。演练发现的「发现」页配置引用错误已在共享入口
修复并补回归。该演练与前述宿主维护 starter 不是同一交付物。
公开投稿、市场已合并与正式客户端可发现分别验收，不把本地测试市场称为已上架。

当前包与本地验收记录见 [VERIFICATION.md](VERIFICATION.md)。
如果开发目录的 `runtime` 是旧构建的共享链接，原生回归需要显式设置
`DESKTOP_TEST_RUNTIME` 为本次隔离构建或新包的 `resources/runtime`；
不要为了测试覆盖共享链接中的 helper 文件。
