## 阅读摘要

- 已确认：旧用户有效选择不被新默认静默替换；先做兼容分类、预检与明确提示，补填另阶段交付。
- 已确认：普通兼容更新沿用一次明确的更新操作，不追加确认弹窗；阻止时原位说明原因和下一步。
- 更新入口方向：卡片和详情页保留统一的“更新”按钮；点击后遇到需处理的占用，再按需呈现二级处理界面，不增加常驻的重启更新按钮。
- 新增体验诉求：MCP 占用时提供释放占用并完成更新的入口；建议与本轮同专题推进，作为独立交付项，不仅补提示文案。
- 本轮实施边界：schema 变化只放行不带宿主声明或宿主绑定的普通独立 `json-file-v1` stdio 消费者；暂不迁移宿主模式选择或新增授权。schema 不变仍遵守原有服务/来源/授权门禁。
- 关键规格：三轴预检及操作、配置状态分支、版本化事务与恢复、reader 修订及本次产物边界。
- 独立议题：WebUI 继续由 Issue #237 讨论；维护者决定后续做预览再取舍，不预先确定内嵌或外置路线。
- 审查状态：三位子代理复审实现与失败路径，并分别补充事务、运行时恢复及浏览器验收；以实际执行结果为准，不将审查意见当作发布证明。

### 本轮实现矩阵

| 范围 | 当前实现 |
| --- | --- |
| 配置兼容 | 聚合全部差异；允许展示调整、enum 保留旧值并增加选项、无 default 的非秘密可选新增 |
| 保守阻止 | default 增删改、必填新增、secret/消费者/服务变化、删除或改类型/约束、复杂 host 绑定迁移 |
| 配置状态 | 活跃配置从已验证快照派生新 revision；未配置保持未配置；撤销保持撤销；历史快照不改写 |
| 统一入口 | 仍从“更新”进入；就绪直接应用；占用或阻止才展开二级处理；处理失效后重新预检 |
| 自动释放 | 仅 Windows 上由宿主从启动起纳入 Job Object、已有非空持久历史的空闲会话；核对整个 Job 已无进程，不以一条停止响应作证明 |
| 会话保护 | 运行任务、队列、Goal、Cron、后台代理、审批、外部任务及状态未知均不强停；受影响的 Remote 绑定不自动解绑 |
| 恢复 | 保持 runtime/session 身份、原历史分支、模型、effort、持久权限、当前选择和未读状态；不重放进程级 Full Access |
| 故障边界 | 普通写入失败回滚，确认释放的会话逐一尝试恢复；写进度失败不跳过恢复；进程中断后不自动重放重启许可，结果未知时保留现场 |
| 非本轮 | 必填补填、默认行为确认迁移、任意作者迁移脚本、WebUI、非 Windows 自动释放、自动发布 |

真实运行时在刚创建的空会话中会先返回历史路径，但此时文件未必已经落盘。
本轮不为自动重启伪造历史或升级 runtime pin；受影响会话没有可用历史时，
预检直接阻止并说明下一步，不等到用户确认释放后才失败。
无此插件占用的空会话不要求重启，因此不因缺少历史额外阻止更新。
当前固定运行时重开时会追加能力声明与技能发现元数据。恢复核对旧叶仍在当前祖先链，
并只允许同会话的这两种已知启动元数据延续；不将其误认成分支切换，也不放行任意自定义条目。
这是可信运行时记录的一致性检查，不是对恶意插件伪造记录的来源认证。

> 作者应能通过实际使用逐渐完善插件，而不是为了避免升级成本，

> 更新时尽量保留用户已有的投入，只让用户处理本次变化真正需要处理的部分。

## 3. 已形成的产品方向

- 兼容新增设置尽量保留原配置，不要求用户从头安装和填写。
- 确实缺少必要信息时，只补缺失项；取消不替换旧版、不丢旧配置。
- 不兼容或涉及授权的变化，说明影响后再迁移、确认或阻止。
- 显示文案、字段结构、已存值有效性及运行权限是不同维度，不以字节差异替代全部判断。
- 配置默认值是持久偏好；插件可允许单次调用显式覆盖，不把默认偏好变成能力限制。
- 默认值变化不静默改变旧用户的有效选择；该原则已于 2026-11-12 由维护者确认。
- 宿主不为 StepAudio 硬编码业务设置或专属工作台；以它作为通用机制的验收场景。

以上是设计方向，不表示所有“可选新增”均可自动证明安全。
宿主只能判断已公开的结构与配置兼容性，不能证明新版代码的全部行为。

## 4. 首阶段：兼容性分类与更新预检

### 4.1 双重判断，而不是删除哈希校验

保留原始包指纹和 schemaHash，继续绑定准确内容。
增加宿主持有的结构化比较，输出“允许保留配置”“需要补填”或“暂不支持迁移”的原因。
兼容性结果不能替代同源、更高版本、候选未变、运行占用及授权等原有门禁。

结构比较应使用已校验的声明，以稳定字段 ID 匹配。
未知字段、重复 ID 或不支持的声明必须拒绝，不因解析器忽略它们而视作兼容。
仅规范化后计算新哈希不能解决问题：旧快照、绑定和 reader 仍需安全转换。
先收集完整差异，再作整体判断；同一更新混有展示变化和不支持变化时，
不能因为先命中某个白名单就放行。字段约束、默认值的属性存在性和类型化值均参与比较。
这里判断配置结构兼容，不承诺新版业务代码、网络行为或代码内回退与旧版完全一致。

### 4.2 建议的首阶段分类

| 变化 | 建议处理 |
| --- | --- |
| JSON 格式、字段 label/help、分组标题和展示排序 | 校验合法后视作展示变化；按字段 ID 保留值 |
| enum 选项标签变化，或只新增选项且旧值仍合法 | 结构上允许保留；不自动替用户改选新项 |
| 新增非 secret 可选字段，不存在 `default` 属性，且缺省语义有说明 | 可列入兼容白名单，缺失值继续缺失 |
| 新增、删除或修改任何显式 `default`，包括 `false`、`0`、`""` | 不静默改变旧用户有效选择；首阶段不自动放行，说明需另行确认的默认行为 |
| 新增必填字段，没有可靠旧值或安全默认 | 预检标为需补填；补填流程实现前保留旧版并说明 |
| 新增 secret、改 secret 属性、消费者或服务声明 | 单独检查凭据接收边界；不因“可选”就复用或授予秘密 |
| 删除、重命名、改类型、收紧约束、移除已选 enum 值 | 暂不自动迁移，明确列出不兼容原因 |
| 来源或安装实例发生变化 | 不自动继承配置或 Key，不使用同名 ID 认领秘密 |

默认值变化不简单等同于危险，但它可能改变旧用户的实际行为，
不能只根据“旧字段类型没变”就认定完全兼容。
保留旧行为是已确认的产品原则，不表示已经确定如何重建所有历史有效值：
字段缺失不等于显式 `false`、`0` 或空串，不以 truthiness 判断有无默认或已存值。
旧 schema 的声明默认与插件代码自身的回退也不同；不运行旧插件探测隐含默认。
无法可靠确定旧值时，不用候选新版默认值替用户做决定，也不宣称完整业务行为已保留。
字段语义变化而 ID/type 不变，也无法靠结构比较发现；作者仍需发布说明和审核。

### 4.3 预检与提交必须分开

建议流程：

1. 用户检查更新，宿主读取旧包、候选包及当前配置的精确修订。
2. 生成分项结果：可保留内容、需补充内容、未支持变化和运行占用。
3. 首阶段只有兼容且就绪的候选允许明确应用；需补填或默认行为确认时只解释原因、保留旧版。
4. 提交前重新检查来源、候选指纹、旧安装及配置修订；任一变化要求刷新预检。
5. 提交成功后区分“新版已安装”和“当前会话已加载新版”，不在用户未授权时重启或改变授权；显式的占用协助流程见第 4.7 节。

维护者已确认更新交互：用户点击“更新”后，兼容且就绪的候选可经预检和提交复审直接应用，
不再要求第二次普通确认。若用户仅点击“检查更新”，则只生成预检，不视为同意应用。
暂不支持或需要补填时，在原位置显示原因和下一步，不反复提供无意义的重试。
未来涉及行为或授权变化时，再设计针对该变化的确认，不对所有更新一律增加弹窗。
占用协助仍从同一个“更新”按钮进入；需解释影响或追加明确动作时，才进入第 4.7 节的二级处理界面。

预检不是锁定未来状态，也不是后台自动更新。
显示变化摘要只使用字段 ID、标签、类型及秘密是否存在，不把 Key 放入 UI、日志或诊断。
预检可产生受限候选缓存，但不改已安装包、安装记录、活跃配置、服务开关或授权，
不启动插件，也不创建含秘密的候选设置快照。

预检结果分为三个独立维度，名称仅为设计用语，不预先规定 IPC 字符串：

| 维度 | 结果示例 | 用途 |
| --- | --- | --- |
| 配置兼容性 | 可保留、需要补填、暂不支持、无法判断 | 说明声明和已存配置能否衔接 |
| 当前就绪性 | 就绪、服务占用、预检过期、来源或状态未知 | 说明现在是否可提交，不将暂时占用当不兼容 |
| 提交结果 | 尚未写入、正在应用、已提交、已回滚、恢复待处理 | 说明磁盘事实，不以一个“失败”覆盖所有结果 |

首阶段的操作约定：

| 情况 | 可提供的操作 | 不应提供的操作 |
| --- | --- | --- |
| 兼容且就绪 | 用户一次明确更新操作，经预检及复审后应用；可查看说明 | 追加普通确认弹窗、静默更新或自动重启 |
| 需要补填、默认行为待确认 | 查看缺失项或原因、查看说明、保留旧版 | 尚未实现的补填按钮、无条件更新或原样重试 |
| 暂不支持、状态无法证明兼容 | 查看具体原因；状态改变后重新预检 | 用“重试”假装当前候选可通过 |
| 服务占用且可确认影响范围 | 从“更新”进入二级处理界面，查看占用会话并明确选择协助更新 | 增加常驻的多套更新按钮、强停运行中任务、只重启当前会话就假定全局已释放 |
| 预检过期、瞬时查询失败 | 重新检查，保留未应用状态 | 复用过期许可、将状态未知当作可安全停止 |
| 恢复待处理或提交结果未知 | 保留现场，进入已有恢复诊断流程 | 重装覆盖、重复提交或承诺旧版仍可用 |

renderer 只提交宿主签发的候选/预检引用和用户明确动作，不提交任意文件路径，
也不能用自报的兼容性、哈希或授权字段绕过复审。实际接口复用现有窄桥与管理锁。

### 4.4 与配置绑定及事务的一致性

当前更新事务在不改变 settings 快照的前提下更换包并更新绑定指纹。
一旦接受 schema 变化，不能只修改绑定上的 schemaHash：

下列快照派生只适用于已配置且验证通过的活跃绑定。
未配置/已撤销分支不创建配置快照；事务记录对应空绑定或明确撤销状态，
并保持其配置/授权状态，不因包更新而初始化配置。

- 以已验证的旧快照生成新 schema 对应的私有快照，不就地覆盖旧快照。
- 对允许保留的字段按 ID 复制，校验候选 schema；秘密保持既有保密边界。
- 新包、安装记录、配置绑定及新快照必须形成可恢复的一致提交。
- reader 的 revision/stamp 变化与运行中服务的处理需要一并设计和测试。
- 中断时恢复为完整旧状态或完整新状态，不允许新包读取错配旧配置。
- 恢复日志、诊断、渲染器消息不得携带秘密。

迁移需要版本化的事务记录，不能只给现有日志补一个 schemaHash：
至少绑定旧/新包指纹、完整旧/新配置绑定元数据、快照引用及各自内容哈希，
日志只存元数据和引用，不含 values、secrets 或 renderer 可指定的路径。
准备、提交和清理各阶段均可复审和恢复；旧 Desktop 遇到未知事务格式必须阻止管理写入、
保留现场，不执行作者迁移代码或尝试猜测性回滚。

旧读取器兼容性也是实施门槛，不假设宿主单方面重写绑定就能让所有插件正常工作。
同一安装仍有旧进程持有 stamp 时，不将新绑定解释成热更新成功；保持原有释放/重启门禁。

### 4.5 首阶段支持的安装与配置状态

这里讨论的是迁移实现的先后顺序，不是限制作者未来能修改什么。
“不带宿主模式绑定的普通 MCP 插件”指只使用本轮支持的配置交付路径，
没有额外宿主模式声明或选择绑定；它不等于宿主模式中的 `independent` 选项。
后者即使使用自己的 Key，仍有模式选择与配置修订等绑定，需要一起迁移。
维护者授权开工后，本轮按以下较窄范围实施；这不是对后续扩大迁移范围的预先批准。

schema 字节不变的更新继续沿用已有路径，不把原先支持的普通更新重新定义成迁移。
仅在 schema 变化时进入本轮新路径，且首阶段须同时满足：

- 同源、唯一、来源已记录的安装实例，旧/候选均是支持的普通 `json-file-v1` stdio 消费者。
- 旧/候选包均无 `dfsc.host.json`，该安装实例也不存在宿主模式选择指针。
- 不涉及专用宿主适配、远程配置消费者或服务结构变化。
- 包、配置状态和差异均可完整验证，且所有差异都命中兼容白名单。

宿主模式选择指针位于 `desktop-plugins/host/bindings/<instance>.json`。
任何指针、声明或无法验证的状态都不当作“未选择”；失效指针也不能忽略。
这些 schema 变化首轮明确提示“宿主模式配置迁移暂不支持”，
不自动复制或续接运行期 grant。宿主模式原有更新路径另列回归，不在本轮悄然修复或扩展。

| 旧配置状态 | 首轮兼容更新后的状态 |
| --- | --- |
| 已配置且绑定/快照验证通过 | 只从该活跃快照生成新 revision；保留合法已存值和相同 secret 字段的值 |
| 从未配置、无绑定 | 仍未配置，不凭 schema 或代码回退创建已授权配置 |
| 绑定已明确撤销 | 仍撤销，不扫描历史目录找“最近可用”秘密 |
| 绑定、快照、实例或指纹损坏/不匹配 | 阻止并保留现场，不降级成“从未配置”来重置 |

预检须绑定配置状态和绑定摘要，提交前复审，避免将预检后发生的撤销或重新保存覆盖掉。
新增必填等未支持变化仍按首轮规则阻止，不因原实例未配置就显示为已就绪。

### 4.6 本次事务产物与秘密留存

预检和取消不写秘密候选；提交准备后，同一事务最多创建一个新 revision，
重复点击、重试和崩溃恢复不得持续生成孤儿快照。
回滚完成后的候选快照，仅在精确归属明确且无活跃绑定或待恢复事务引用时清理。
无法确认或清理失败时保留精确事务记录与可见 warning，不盲删、不重复叠加产物。

既有历史快照维持现有存储行为；本轮不新增全局扫描/GC，
也不擅自删除旧历史秘密来简化迁移。未来改变历史留存策略需独立讨论。

### 4.7 释放占用并完成更新

这是维护者新增的实际体验诉求；建议纳入同一更新体验专项，以独立交付项或 PR 验收。
目标是由宿主组织必要步骤，不要求普通用户理解并手动执行“停开关、重启、更新、再开启”。
维护者已批准首轮实施，当前实现候选采用受保护的整个会话运行时释放与恢复，
不预先承诺当前运行时支持单独热停一个 MCP 服务；本地验收状态见 `VERIFICATION.md`。

#### 统一入口与按需二级界面

维护者提出卡片和详情页只保留统一的“更新”按钮，在点击后遇到占用时呈现二级界面。
本稿采用这一交互方向：不在第一层并排添加“暂停服务并更新”“重启相关会话并更新”等按钮，
也不把所有普通更新都变成多步向导。

- 点击“更新”先执行预检；兼容且就绪时直接继续，不打开二级确认。
- 可处理的占用属于待处理条件，不先包装成“更新失败”再要求重试。
- 需要用户处理占用时，按需打开与原插件更新入口关联的处理面板或紧凑对话框，
  保持插件名称、目标版本和返回位置清楚；关闭后回到原更新入口，不跳去通用设置页。
- 同一二级界面说明占用原因、受影响会话、是否必须重启及可能丢失的运行时临时状态。
  只展示实际需要的内容，详细诊断另行展开，不让用户手动编排内部步骤。
- 相关会话均可安全处理时，界面内提供“暂停服务并继续更新”或“重启相关会话并更新”等
  准确命名的主操作，以及“取消”；此动作同时承担影响确认，不再叠加一层泛化确认框。
- 有运行中任务或状态未知时，显示各阻塞项并提供查看入口，不提供可绕过门禁的继续操作。
- 执行后在同一处理界面展示释放、更新和恢复进度及最终事实，不连续弹出多个步骤窗口。
  开始执行后，关闭界面不等于取消事务或回滚；再次查看须呈现真实操作状态，不重复提交。

面板还是对话框属于后续视觉细化；单一入口、按需呈现和明确影响不依赖具体容器。
二级界面不能用轻描淡写的“继续”掩盖重启，也不应把一条“前往 MCP 设置”链接当作完整协助流程。

建议流程：

1. 先检查候选来源、兼容性和可提交性；已知无法迁移时不先停止服务或重启会话。
2. 查询占用该安装实例的会话及阻塞状态。空闲但仍加载服务也可能占用，
   不将“没有正在调用工具”当作已经释放；查询失败明确显示未知。
3. 在上述二级界面内提供准确命名的操作。能仅释放目标服务时，可显示“暂停服务并继续更新”；
   若必须重启会话运行时，显示“重启相关会话并更新”，列出会话与影响后由该动作确认。
   不将这些操作常驻第一层，也不在二级界面上再叠确认；普通兼容更新仍不追加确认弹窗。
4. 在宿主协调锁内复审候选、配置、会话状态和用户授权，再释放已确认空闲的目标占用。
   不仅在 renderer 顺序调用现有按钮；释放必须有可信结果，未确认进程退出时不换包。
5. 重新核对兼容性与修订，执行既有可恢复更新事务；期间不允许新启动重新抢占目标资源。
6. 在明确授权范围内恢复原有启用状态及所需运行时，验证已加载版本。
   不新建或删除聊天，不重发用户消息、工具调用或计费请求；重启保持持久会话历史，
   但不承诺插件内存中的临时状态能无损保留。

实现须拆开“停止并证明释放”与“恢复既有会话运行时”，在两者之间执行更新。
现有 `refresh()` 停止后立即重开，`suspend()` 保留断开 worker，
不能简单顺序调用它们，再让原占用检查查询一个已经停止的 RPC。
释放证据须由宿主绑定精确安装实例、worker、transport 和 session 身份，
并在同一协调边界内供占用门禁核对；不能仅因 disconnected、移出列表或忽略查询失败就放行。
须按平台验证进程树及资源释放，单个父进程退出不自动等于所有占用已释放。
恢复阶段不依赖用户当前选中的会话，也不为恢复后台会话逐个激活它们；
保留前台选择、草稿、未读标记和阅读位置，不能把运行时恢复变成会话导航。

宿主持有操作 ID、目标安装/会话、阶段及必要的原开关修订等非秘密状态，
在开始释放前建立操作记录，并与包更新事务关联；renderer 只观察状态与提交明确动作。
界面关闭后记录仍可查询。跨应用重启时先核对实际安装与运行状态，
原恢复意图或修订无法证明时显示未知或待手动恢复，不通过重放 renderer 步骤恢复。
需要落盘的恢复记录须有版本校验且不含凭据，不另建可绕过原事务门禁的写入路径。

优先通过运行时释放而不是修改持久开关实现临时暂停。
若实现确需临时改开关，必须逐服务保留原始状态并校验修订，不能把原本关闭的服务打开，
也不能覆盖用户在其他窗口的新设置。恢复不续接失效授权或已撤销配置。

运行中任务、后台代理、Goal、Remote、Cron 或待发送消息的阻塞仍遵守原有门禁；
首轮不强停、静默取消、自动解绑或自动删除任务，也不后台排队等待自动更新。
可提供查看相关会话的入口和稍后手动更新，不让用户在无关设置页面里寻找原因。
目标是最小化影响，不默认重启全部会话；现有共享门禁若还受到其他会话阻塞，
应如实列出，不能为了做成“一键”而放松门禁或假装只影响当前会话。

| 中断或失败位置 | 应呈现的事实与操作 |
| --- | --- |
| 确认前取消或预检不通过 | 不改安装、开关或运行状态 |
| 部分运行时已释放，尚未提交更新 | 显示旧版安装事实及哪些服务尚未恢复；仅在旧状态完整且授权仍有效时尝试恢复 |
| 更新失败且完整回滚已确认 | 说明旧版仍安装，分别展示运行时恢复是否成功 |
| 新版已提交，但恢复或重连失败 | 明确“已更新，服务未恢复”，提供恢复入口，不重复更新或声称已在使用新版 |
| 提交或释放结果未知、应用崩溃 | 保留现场，重新核对安装与运行状态；不自动重放提交、强制启动或宣称已回滚 |

一键指一个明确入口组织多步流程，不是无条件一次点击完成所有情况。
这项能力不等于放行尚未支持的 schema、宿主模式或授权迁移。

## 5. 第二阶段：只补齐缺失配置

新增必填设置不等于清空原有设置。建议行为：

1. 使用候选 schema 提示缺失项，并说明为什么需要补填。
2. 已有普通值尽量保留；已有 secret 仅显示已配置状态，不返回真实值。
3. 新输入先作为候选草稿，不修改仍在使用的旧配置。
4. 用户取消、校验失败或候选变化时，旧包和旧绑定不变。
5. 确认后复审全部修订，再按一致事务应用包和配置。

新设置如果只服务一个新增的可选功能，不应仅为方便实现就变成整个插件的必填项；
作者应先评估旧能力是否可以继续工作。

首阶段可以只识别“需要补填”并保留旧版，不能展示尚未接通的补填按钮。
也不以先卸载旧版来简化补填与恢复。

## 6. 更新提示与作者交付

### 6.1 更新提示

沿用并核对已有错误体系，改进的是原因、影响和下一步，不重复建设一套提示：

- 不兼容：说明具体变化、这次是否未替换旧版，以及如何查看更新说明。
- 缺失配置：说明要补什么，不让用户以为原 Key 丢失。
- 占用：区分配置已保存、服务仍使用旧修订及需要显式释放/重启；提供协助更新入口，不只让用户手动停用后重试。
- 恢复异常：保留现场，不把重装作为通用解决按钮。
- 失败时保留可恢复的非秘密草稿，提供刷新或重试；不静默覆盖其他页面的新配置。

普通兼容更新不额外弹确认；不能应用时原位说明具体原因和下一步。
刷新或重试只用于当前确实可恢复的状态，不用于绕过尚未支持的迁移。
未来行为或授权变化另做有针对性的确认，不以一次“更新”点击涵盖新增授权。

文案必须符合实际事务状态。只有确认旧版未被替换且绑定完整，
才能表示“旧版保留”；不能在结果未知时承诺旧版仍可用。

### 6.2 作者文档与示例

- 将官方 SDK 打包、许可证、发布白名单和原生握手串成一条可复现路径。
- 新增一组同源升级示例：展示文字变化、可选字段增加、必填字段增加、不兼容变化。
- 写明哪些是完整性要求、哪些是当前迁移限制、哪些需要用户授权。
- 示例说明未设置、显式设置、默认值和单次覆盖的关系，不引导作者为避更新而全部使用文本框。
- 安装、连接成功、真实调用成功及实际计费验收分别记录，不互相替代。

公开文档和示例改进不能保证 Agent 永不误读，但应减少依靠源码反推规则的必要。

### 6.3 首阶段责任划分与完成条件

| 层次 | 本轮应承担的责任 |
| --- | --- |
| 声明比较 | 对严格校验后的旧/新 schema 输出完整差异；纯逻辑可独立测试，不读取秘密、不执行插件 |
| 管理服务与 worker | 解析宿主引用，核对来源/修订/占用，生成及复审预检；沿用管理串行化边界 |
| 配置与更新存储 | 按配置状态派生候选，完成版本化事务和中断恢复；不借迁移恢复已撤销配置 |
| 受信 reader | 验证新包、新 schema 和新 revision 的一致性；旧进程不热接新绑定 |
| 插件中心 | 展示兼容性、就绪性及提交事实；只开放当前已实现且有效的操作 |

首阶段完成不能只靠比较器单测或静态 UI：
须跑通已有已配置示例从旧版到“只改展示”和“新增无默认可选字段”的真实安装更新，
同时证明预检、阻止和取消不改变已提交安装状态。
未配置/已撤销实例若执行兼容更新，可以更新包，但仍保持未配置/撤销，不恢复秘密或授权。
同 schema 的既有更新、来源冲突、服务占用和宿主模式路径必须有无回归证据。
占用协助更新独立验收，不能把仅新增“前往 MCP 设置”按钮视作完整交付；
须验证释放、更新、恢复与部分失败事实的闭环。

## 7. WebUI 与媒体交互：独立议题

StepAudio 暴露的是“浏览、试听、选择、生成、导出”的操作闭环。
不预设聊天就是完整答案，也不预设任意前端加载器就是唯一答案。
可比较的方向包括受限宿主媒体组件、外置本地工作台和未来的声明式交互扩展。

这一轮建议只起草支持边界，不纳入配置升级实现：

- 是否允许随包附带可选本地 WebUI，以及市场需要声明哪些行为。
- 用户如何发现和显式启动/停止服务；手动终端启动不自动等于非技术用户容易使用。
- 新 WebUI 进程是否可消费托管配置，如何验证身份与授权；同包代码不自动等于新增入口获授权。
- 监听地址、认证、浏览器请求边界、端口冲突、日志脱敏和凭据不可回读。
- 更新、卸载、退出和异常时如何发现并处理 WebUI 占用，不假装宿主已代管进程。
- 音频读取/播放/下载的路径范围、格式和资源上限，不将文件路径本身当作任意访问授权。

不直接采纳原会话中的“localhost 就足够安全”“稳定 token 没有泄露问题”
或“外置 WebUI 不新增凭据使用面”等推断。
具体认证与本地服务方案另行设计、威胁分析和验收。

首轮不做：第三方任意 HTML/JS 加载器、任意迁移脚本、
安装时 npm/pip、后台自动更新、通用明文 Key 导出或跨来源秘密继承。

维护者于 2026-11-12 确认将交互能力独立讨论，并提出参考 AstrBot。
AstrBot 官方文档当前有插件可视化视图方案；这使受限内嵌视图成为需要比较的候选，
不应预先只保留外置 WebUI。研究依据与讨论正文见
[插件可视化工作台讨论](PLUGIN_WEBUI_DISCUSSION.md)；该讨论不代表已开放新能力。
独立跟踪：[Issue #237](https://github.com/7oMB2006/desktop-for-step-code/issues/237)。
本轮只更新本地讨论稿，未执行 Issue 正文同步；不要把跟踪链接当作本地修订已发布的证明。

维护者进一步决定：后续先做预览体验，再取舍内嵌或外置等路线。
这确认了评估方式，不是现在启动预览实现、接入真实凭据或开放正式前端执行能力的指令。
预览范围、模拟与真实能力的界线，在开始该轮工作时明确。

| 是否接受作者提供迁移代码 | 首轮未接受；只做宿主持有的声明式比较和转换 |

| WebUI 与媒体交互是否同批实现 | 已确认独立讨论，后续做预览再取舍；不预定内嵌或外置路线，也不在本轮直接启动实现 |

本轮实施授权不等于批准全部迁移能力、WebUI 授权或发布排期。
后续扩大白名单或新增授权时，仍须重新明确对应行为和验收范围。

## 9. 验收清单

以下是完整验收要求，不代表各阶段都已完成。首轮实际执行范围、失败记录和剩余边界
见 `VERIFICATION.md`；其中补填、复杂宿主迁移、WebUI 与非 Windows 自动释放仍未实施。

| 场景 | 预期 |
| --- | --- |
| JSON 换行、键顺序、label/help、组排序变化 | 合法内容可迁移；原值不被重置，包仍按精确指纹校验 |
| 可选字段新增且无默认 | 旧值和秘密保留，新增值按缺失语义处理 |
| 白名单变化混有未知字段、类型或服务变化 | 一次聚合全部差异并阻止，不因先命中展示变化而放行 |
| enum 只加选项或改标签 | 保留原选择，不因新选项自动改值 |
| default 属性缺失与 `false`、`0`、`""` 之间增删改 | 首阶段均阻止并解释；属性缺失不等于假值或空串 |
| schema 未变或由无到有、由有到无 | 未变沿既有路径回归；清单增删不在首阶段迁移白名单 |
| 新增必填 | 首阶段有明确阻止原因；第二阶段可补填，取消保留旧版 |
| 改类型、删字段、secret 属性或服务变化 | 不自动迁移/授权，给出具体原因 |
| 新增字段仅服务可选功能 | 不无故阻断旧能力，按插件公开契约验收 |
| 从未配置、已明确撤销、绑定损坏 | 前两者维持状态，不认领历史；损坏明确阻止，不初始化覆盖 |
| 协助执行前的预检、取消或阻止提交 | 已安装包/记录/绑定/配置/开关及运行状态不变，无启动、授予或计费副作用；释放后的阻止或退出按第 4.7 节核对，不承诺运行状态从未变化 |
| 预检后用户改配置、候选包变化或市场换源 | 提交拒绝过期预检，不写入错配状态 |
| 多窗口并发、配置写入交错 | 修订冲突可见，不覆盖新值或泄露秘密 |
| 写快照、prepared、换目录、写绑定、committed、cleanup 各阶段异常退出 | 恢复到一致状态；恢复失败保留现场，不引导重装覆盖 |
| 重复点击、候选清理失败、恢复重试 | 本次额外快照有界；精确保留未决事务，不全局删除历史秘密 |
| 旧 Desktop 读取新版本迁移日志 | 拒绝管理写入且不清理现场，不猜测事务状态 |
| 旧/新有 host 声明或实例有任意 host binding 指针 | schema 变化首轮阻止；不得从失效指针推断“没有选择” |
| 旧 reader、运行中服务、Cron/Remote 占用 | 不绕过原有释放、授权与修订检查 |
| 兼容但占用、需补填、不支持、提交不明 | 分别呈现真实可用动作，不全部落入“更新失败后重试” |
| 第一层单一“更新”入口 | 不增加常驻的暂停/重启更新按钮；就绪更新直接应用，仅需用户处理时打开二级界面 |
| 二级处理、影响确认与执行进度 | 同一界面说明原因、影响及准确操作，不再叠泛化确认；执行前取消不改状态，执行后关闭界面不等于取消，重开显示真实结果且不重复提交 |
| 一个或多个空闲会话仍加载目标 MCP | 显示真实影响范围，经明确操作完成释放、更新和恢复，不只处理当前会话 |
| 已停止 RPC、断开 worker、停止失败或残留子进程 | 仅按宿主绑定的可信释放结果处理；不以查询失败、状态 disconnected 或移出列表代替释放证明 |
| 恢复多个后台会话或用户已切换会话 | 按原操作的精确会话身份恢复，不改变前台选择、草稿、未读或阅读位置，不新建聊天 |
| 处理面板关闭、重开或应用崩溃 | 操作 ID 与阶段可核对；不能证明原状态时显示未知或待手动恢复，不重放步骤或恢复已撤销授权 |
| 相关会话忙碌、Remote/Cron 等阻塞，或状态未知 | 不强停、不自动解绑、不换包；显示阻塞项及查看入口 |
| 预检已知不支持，或用户在中断确认前取消 | 不为不可应用的候选先停服务或改开关 |
| 预检后新任务开始、窗口改开关或撤销授权 | 协调锁与提交复审阻止竞态，不覆盖新选择或恢复已撤销能力 |
| 释放部分成功、更新回滚、新版提交后重连失败 | 分别显示安装版本和运行恢复结果；不笼统报失败后重复更新 |
| 服务原本关闭、混合启停，或恢复后仍未核实版本 | 保留逐服务原状态；不自动全开，不声称运行中已是新版，不重放历史调用 |
| 新版已安装但运行修订未确认 | 显示待加载/待重启或未知，不声称正在使用新版 |
| 卸载重装、fork 或同名不同来源 | 不自动接走旧实例秘密 |
| UI、日志、事务及诊断输出 | 无原始秘密，无任意路径写入或未授权秘密回读 |

先做结构比较和转换单测，再扩展原生更新事务/并发/中断回归，
最后用隔离 Desktop 数据目录验收两个真实插件版本的更新与取消。
涉及实际平台支持的项目按 Windows 和 macOS 分别验证。
本地 fixture 不能替代打包版、真实账户或 TTS 业务调用验收。

## 10. 建议交付拆分

以下保留设计时的拆分建议。本轮在同一独立工作区联合实现第 2/3 项及对应文档，
完成本地验收；PR、合并、打包与发布状态分别记录，不表示其他阶段已经实施。

1. **设计与证据**：本文、规则表和待复现场景；不新增运行能力。
2. **升级基础**：严格兼容分类、更新预检、快照/绑定一致迁移和错误提示。
3. **占用协助更新**：独立 PR 串起影响说明、空闲占用释放、更新及恢复，保留原有任务保护；与升级基础同专题推进，不扩展迁移白名单。
4. **补填升级**：候选表单、取消保留、修订复审与可恢复提交。
5. **作者示例与文档**：随已实现能力同步更新，不提前承诺未支持迁移。
6. **交互能力评估**：独立开展可视化工作台候选预览与必要技术验证，再决定支持路径。

每一步单独记录设计、实现、测试、打包和发布状态。

本轮实际支持矩阵与排除项已列于阅读摘要，后续实现 PR 仍须明确列出供维护者确认，
