# 插件信任与运行边界

日期：2026-11-14。本文说明 DFSC 的产品边界和当前接入规则，不代表所有已发布包
均已包含本分支修复。实现与验收状态见 [验证记录](VERIFICATION.md)。

## 当前范围

DFSC 是社区维护的 Step Code 桌面客户端，不是任意代码插件框架。
市场统一发现与分发，不意味着所有内容共用一种执行方式或取得相同权限。
当前优先使用两条已有路线：

| 路线 | 当前接入方式 | 不因此获得 |
| --- | --- | --- |
| 声明式资源 | 受限主题、图片、Markdown、技能与提示命令等已有格式，由宿主或运行时读取 | 任意前端脚本、Electron 主进程接口或宿主账户权限 |
| 外部功能服务 | 原生 MCP 声明及已支持的配置/宿主能力协议 | 恶意代码沙箱、自动账户授权或不受限的宿主 API |

权限按实际声明和执行内容判断，不按名称、分类或“美化插件”标签判断。
纯数据主题不需要 MCP，也不应为了被安装而附带无用途的服务。
技能和提示命令虽然不是原生程序，仍可能影响模型行为，不能把资源型插件一律描述为无风险。
一个包可以同时包含资源与服务；其中的服务仍遵守独立的启用、连接与授权规则。

目前没有第三方 HTML、iframe、React bundle、任意 JavaScript 入口加载器、
在宿主内生成并执行插件的创造模式，或通用恶意插件沙箱。
桌宠皮肤只有符合已有资源协议时才能作为数据使用；交互桌宠涉及的窗口、后台进程、
会话监听等能力不因“桌宠”名称自动受支持，需另行设计接口和生命周期。
不以本轮故障修复承诺将这些能力一起实现。

## 安装、连接与调用

以下状态不能合并成一个“已启用”或“安全可用”结论：

| 状态/动作 | 当前含义 | 不表示 |
| --- | --- | --- |
| 已收录 | 市场登记了来源和可安装内容 | 作者身份已认证、代码全面审计或安全保证 |
| 已安装 | 插件资源及安装记录已写入 Desktop profile | 本体依赖齐全、服务已连接或宿主模型已授权 |
| 服务已启用 | 配置允许对应 MCP 消费者参与后续运行时连接 | 当前会话已重载、只在需要工具时启动或已执行业务 |
| 自动连接 | 会话运行时准备已启用服务、握手并取得工具目录 | 用户要求了该工具、模型已选择它或业务调用已成功 |
| 当前会话已连接 | 该会话已取得对应工具及连接状态 | 所有其他会话相同、账户可用或实际任务成功 |
| 实际工具调用 | 用户或模型通过工具接口执行了业务 | DFSC 已审核所有数据用途、外部费用或业务结果 |
| 宿主能力授权 | 已支持协议下的特定安装实例、会话及能力获得允许 | 整个插件的所有代码、未来版本或其他服务被一并信任 |

当前原生 MCP 在会话运行时准备阶段发现并连接已启用服务，不根据首条自然语言问题
判断是否需要该工具，也没有完整的按需懒加载框架。启动 `dfsc.host.json` 声明的消费者
还须等待宿主核验及有效模式；没有有效模式或配置时，不应据“已安装”默认跟随账户。
自动连接可能执行插件入口、发起网络握手或其他启动行为；作者必须披露这些行为，
不能承诺只有工具调用才会产生文件、网络或外部服务活动。

服务开关控制精确消费者标识，不是插件资源卸载按钮。插件消费者采用
`<plugin-id>__<server>` 名称；名称相似的手工 MCP 不自动等价，也不能静默互相迁移。
保存开关或配置不即时卸载技能、命令，不承诺断开已有会话；按界面要求显式重启后
核对真实连接。插件配置、会话状态和实际调用结果应分别验收。
插件中心的开关反映当前 Desktop profile 配置；作用域与项目配置覆盖遵循原生运行时规则，
不能据此保证每个项目中的最终有效配置或已有会话状态相同。

## 完整性不等于代码安全

固定来源、提交 SHA、内容指纹及安装凭据用于确认“当前是什么内容、是否与记录一致”。
它们可以发现不一致或改变，但不能证明原内容没有恶意，不能替代对作者和依赖的信任。
不以重复扫描无关插件作为基本聊天或目标服务启动的必要条件。

原生 MCP 及其依赖可能以当前系统用户权限访问文件、网络或启动进程。
DFSC 不提供针对恶意本机插件的 OS 沙箱；主进程/renderer 分离、路径校验、
配置秘密不可回读和 broker 权限绑定也不构成此类沙箱。
秘密对界面不可回读，不等于获准消费它的程序或同一用户下的恶意本机代码无法读取。

安装、服务开启、Full Access、插件自报能力和市场署名都不自动授权宿主账户或模型额度。
宿主支持的模型能力须按实际协议显式配置、核验及确认；不能把该协议的授权
描述成对所有插件网络行为的管控。独立服务自行使用其凭据时，数据用途和计费规则
还取决于服务及作者实现。

## 作者与维护者的责任边界

作者应在实际发布内容及投稿说明中列明：

- 源码、发布目录、版本、许可证和所需运行时/外部服务。
- 启动及工具调用期间的文件、网络、子进程行为和数据发送对象。
- 模型、凭据、账户、套餐或费用需求，以及所测宿主、平台和未验证范围。
- 新版本增加或改变的权限、数据用途、运行依赖及费用行为。

作者交付的是可安装发布目录，不是开发工作目录。优先使用自包含构建及最小发布白名单，
保留必要文档、资源和第三方许可证；不携带 `.git`、秘密文件、开发缓存或用户状态。
需要随包携带的运行依赖应明确说明并按发布检查规则处理，不能把开发依赖目录
无差别复制进包。开发仓库、测试市场、正式市场和安装副本应使用可复现的同一发布内容。

维护者审核声明和变更、维护来源与完整性边界，处理已知缺陷、已知恶意及严重风险，
必要时阻止新安装、停用收录或发布修复。规模有限意味着不承诺全面审计所有代码和依赖，
不意味着可以忽略已知问题或由任意插件阻塞基本聊天。
风险说明不替代这些工作，也不把尚未完成的检测、隔离或验收写成既有保障。

## 市场风险说明

市场与关键安装入口可使用下面的统一含义，不把它写成安全认证或免责承诺：

> 社区插件由各自作者维护。市场收录和完整性校验不构成全面安全认证。
> 功能插件可能以当前系统用户权限运行，访问文件或网络，并使用第三方付费服务。
> DFSC 不提供恶意插件沙箱，请仅安装和启用你信任的插件；安装前核对来源、
> 执行内容、依赖、数据用途及费用说明，发现问题请停用并反馈。

这是产品信任边界说明，不表示现有所有安装包已经新增相同风险确认界面。
作者接入与交付细节见 [插件作者规范](PLUGIN_AUTHORING.md)；
受限宿主模型能力见 [宿主协议候选](PLUGIN_HOST_CONTRACT.md)。
