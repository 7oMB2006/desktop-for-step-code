## 背景

维护者通过模拟普通下游作者开发 StepAudio TTS 插件，发现聊天调用之外的需求：
浏览音色、试听比较、选择、输入文字、生成、播放与导出。
仅展示文档或返回文件路径，不必然完成这些人机操作。

需要讨论的不是立即开放任意第三方前端，而是：

> 插件作者如何交付必要的交互工作台，用户又如何发现、打开、使用和关闭它，
> 同时保持来源、凭据、文件和运行生命周期边界清楚？

已完成上述文档与源码阅读，不是 AstrBot 实包验收或攻击验证，也不证明所有版本均支持。
不把该机制误写成“每个插件独立开一个固定端口”，也不将它等同于完整恶意代码沙箱。
借鉴目标是页面、后端与宿主边界的分层，具体技术形态需要适配 DFSC。

尤其要区分：

- iframe 隔离父页面，不自动把原生插件后端变成低权限进程。
- 消息来源校验不等于禁用所有页面外连；本轮所见 CSP 不能作为全面禁网的证据。
- AstrBot 的插件/视图令牌范围，不能直接代替 DFSC 的安装实例、包指纹和配置修订绑定。
- 卸载视图时清理消息监听和 SSE，不能据此承诺后端任务已停止或费用已撤销。

## 必须比较的候选

下表是 DFSC 的设计候选，不是已有能力。

| 候选 | 产品价值 | 需要回答的问题 |
| --- | --- | --- |
| 外置本地 WebUI，由用户明确启动 | 插件可以独立迭代，也可服务其他 MCP 客户端 | 启停入口、端口、认证、占用识别，以及是否允许消费托管配置 |
| 受限内嵌插件视图，经窄 bridge 通信 | 用户不必离开 DFSC，入口和主题可统一 | 隔离渲染、消息验证、后端身份与路由、权限、资源版本及销毁 |
| 宿主提供媒体播放、选择与导出等通用组件 | 少量交互无需每个作者维护完整前端 | 可表达哪些任务，何时仍需自定义工作台 |

可以分阶段支持，不要求现在三选一，也不将当前无加载器当作永久不允许的结论。
受限内嵌视图是正式候选，不预先批准任意 HTML/JS 在宿主主渲染器中执行。

先前建议优先研究“受限内嵌视图 + 窄后端通道”，理由是减少用户手动启动服务、
管理端口及切换应用的负担，而不是假设内嵌天然更安全。
维护者现决定后续通过预览体验再取舍；不将该建议固化为已经选定的研究或实现路线。
预览开始前明确比较问题、隔离范围、模拟与真实能力，不要求先完整实现两套正式系统。

## 讨论问题

1. **发现与入口**：工作台如何出现在插件详情；是否仅用户点击后启动；打开与启用服务如何区分？
2. **后端通道**：页面调用插件现有 MCP 工具、专用 UI 协议还是独立 HTTP API？如何避免用户操作依赖 LLM 转述？
3. **凭据与计费**：页面不能直接读取原始 Key；调用哪一个账户、谁获得使用权，以及计费动作如何告知和确认？
4. **资源边界**：音频、上传、下载和结果文件如何按安装实例与任务授权；避免把任意路径或 URL 当作权限？
5. **生命周期**：关闭视图是否停止服务和生成任务？更新、卸载、停用、退出及崩溃时如何处理占用与取消？
6. **来源与修订**：页面、后端和配置是否绑定同一安装实例、包指纹和修订？更新后旧页面如何失效？
7. **可访问性与兼容**：主题、键盘、焦点、无前端宿主降级及错误重试如何交付？
8. **作者交付与审核**：静态资源怎样构建和固定来源；允许什么依赖、网络及持久化行为；如何描述已验收范围？

不能因“本机服务”就省略认证与浏览器请求边界，也不能因“同一插件包”
就自动赋予新增进程或页面消费托管秘密的权限。

## 形成方案前必须补齐的三条通道

以下是 DFSC 的候选约束，不声称 AstrBot 已提供相同保证。

### 1. 操作与授权通道

bridge 需要宿主持有的操作白名单、插件后端身份、参数/结果限额和授权复审。
不能用“任意 endpoint + 任意参数”把插件页面变成宿主通用权限入口。
renderer 不持有原始 Key、broker token 或任意 IPC；视图授权与模型调用授权分开。
页面联网策略须单独明确，不能只写“已 sandbox”。

### 2. 有副作用任务的状态通道

一次显式生成应关联一个可查询的任务标识，至少区分未提交、已接收、运行中、
结果未知、已完成、取消请求已发出和已确认取消。
断连、刷新或 bridge 超时不自动重发生成请求；重开优先查询原任务。
不能确认原任务状态时明确显示未知，不伪造失败后无副作用，也不承诺第三方服务精确一次执行。

关闭页面与取消任务分别定义；取消请求已发出不等于取消已生效，
取消已生效也不承诺退回已发生费用。是否提供跨重启恢复由方案另行限定。

### 3. 试听与导出的资源通道

研究路径应覆盖：

```text
插件后端生成
    -> 不透明结果资源引用
    -> 校验安装实例、权限与资源寿命
    -> 限定类型、大小和读取范围
    -> 页面播放或用户明确导出
```

下载 helper 不等于原地试听已经可用。不能用原始 Key、任意绝对路径、
无期限裸 URL 或无限大小的 bridge JSON 解决音频传输。
资源失效、权限撤销、文件删除及读取中断均需明确状态。

## 产品验收场景

- 用户从插件详情进入音色库，选中并试听，再输入文字、生成、播放和导出。
- 显示账户/配置来源和操作状态；Key 不返回页面、日志或普通诊断。
- 用户可取消、重试或离开；离开后任务继续还是停止有明确规则。
- 页面刷新、断连、超时和重复点击不静默重发生成请求；未知结果先查询原任务。
- 取消请求、确认取消与已发生费用分开显示，不把关闭视图当作成功取消。
- 服务未连接、端口冲突、凭据缺失、生成失败和文件失效都有明确状态。
- 试听使用有界且可撤销的资源引用，不依赖页面读取任意文件或持有 Key。
- 更新、卸载或撤销权限后，旧页面/连接不再继续消费旧授权。
- 可选工作台缺失不回归既有 MCP 等非 UI 能力；UI 必需型插件明确声明最低宿主能力与不支持状态，不强求等价 CLI。
