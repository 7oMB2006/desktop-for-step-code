# Remote 管理门控治理

日期：2026-11-10

## 目标

Remote 绑定表示远端仍拥有会话连接，不表示会话正在执行任务。
不再仅凭绑定阻止不重启会话的插件和设置管理；保留任务、插件资源、
共享写入、恢复记录和运行环境替换的保护。

## 操作边界

| 操作 | Remote 绑定 | 其他保护 |
| --- | --- | --- |
| 市场查询、刷新、检查更新、已验证纯主题管理 | 保留既有放宽 | 保留来源、指纹、事务与资源检查 |
| 插件安装、更新、卸载、开关，MCP/技能管理 | 允许保留绑定，不重启会话 | 仍要求会话空闲；更新/卸载仍须确认实际插件服务已释放 |
| 插件配置、宿主来源、旧 BVR 配置保存，技能导入 | 允许保留绑定，仅保存管理状态 | 保留共享写屏障、配置修订和授权撤销；不声称已热应用 |
| 固定指纹 StepPage 准备 | 允许保留绑定，不替换驻留 MCP 连接 | 仅此操作保留已知就绪 Cron 待命例外；未知状态、实际任务和重启保护不放宽 |
| 既有插件更新恢复回调 | 保留绑定，不替换会话运行时 | 两次空闲检查、实际资源释放、恢复指纹和隔离保护；不新增恢复入口 |
| 登录、退出登录、应用 provider、重启、删除/迁移会话 | 不放宽既有 Remote 所有权保护 | 不自动解绑、不自动重启、不修改现存任务 |

## 实施计划

1. [x] 子代理审查本计划，核实所有放宽的操作确实不停止或替换 worker；
   检查 Remote 输入、待确认回复和后台调度在共享写入期间的互斥。
2. [x] 在 Electron main 统一不重启写入的门控语义；仅宿主决定放宽，
   不接受渲染侧 `allowRemote` 等绕过标志。覆盖插件配置、技能导入、
   StepPage、MCP 保存、能力管理及恢复；默认/破坏性门控维持严格。
3. [x] 增加实际 main IPC 与 SessionRuntimes 回归：空闲 Remote 可管理；
   绑定、worker、RPC、sessionId 不变；忙、排队、审批、Goal、Cron、
   后台任务、状态查询失败、插件占用仍拒绝；异步观察后再次核对。
4. [x] 更新现有原生 Electron 管理验收，验证允许写入、不解绑不重启、
   写入期间禁止新增远端任务，释放屏障后可继续输入；保留真实占用、
   文件锁和恢复失败证据。运行定向测试、类型检查和生产构建。
5. [x] 实施后再做代码审查，记录验收结果与尚未覆盖的边界。

## 不包含

- 不把 `allowRemote` 改为 SessionRuntimes 的默认值。
- 不允许运行中的插件目录被替换，不强制杀死 MCP，不自动恢复任务。
- 不新增“所有插件可热更新”的承诺，不放宽未知运行状态和文件锁。
- 不自动迁移 BVR 0.1.1 → 0.2.0 的配置或服务声明变化。
  Remote 门控修复与配置迁移是两个独立结果，后者仍须单独设计和验收。
- 不改上游 runtime pin，不变更真实用户 profile、快捷方式或正在运行的应用。
- 本轮未请求打包、发布市场、合并或替换日用安装。

## 交付验收

必须有真正经过生产 main handler 的 Remote 绑定管理成功场景，
不能只证明 `SessionRuntimes` 接受一个选项。保留重启类拒绝用例，
不能通过删除旧测试来“修复”。单元测试、隔离原生验收、云端 CI、
用户实机旧版升级与打包验收分别报告。

## 计划审查结果

采纳子代理 Beauvoir 的三项意见：

- 明确不重启的资源写入默认同时启用 Cron 保护，防止仅有共享写屏障、
  却放行驻留 runtime 自行触发的计划任务。
- 恢复回调保留直接运行时检查，不复用会拒绝调用方 `transition` 的
  外层门控，避免连接恢复流程自锁。
- 恢复范围只调整现有回调，不声称提供新的管理入口。

补充：Remote 会话连接状态不明、RPC 返回了其他会话或缺少可判断的
运行状态时拒绝写入。默认和重启检查不改变。

## 实施后审查

再次交由同一审查代理独立复核，并修复两处 P2：

- 进程退出会自动清除 Remote 绑定标志。单会话与全局检查现在保存初始连接
  要求、RPC 和会话身份，最终检查不能被自动解绑绕过。使用真实
  `SessionRuntimes` 退出事件和 `RemoteManager.dispose` 复现两例失败后修复。
- 统一资源门控不能误伤已有的 StepPage/Cron 共存。只有固定指纹准备操作
  明确选择待命例外，并重新解析校验 Cron 状态；未知、畸形、跨 RPC 变忙、
  已访问会话迟到变更及重启仍拒绝。保留原 StepPage 原生验收，而非修改预期。

StepPage 例外依赖固定文件校验、配置锁和驻留 MCP 连接隔离，
不依赖共享写屏障能够暂停上游 Cron。尚未单独自动化“下载暂停期间恰好到期”
的原生时序场景，不据此承诺暂停调度。

末次独立复审确认上述修复及无 Remote 的 Cron 重启断言，
无未解决的 P1/P2 阻断。
