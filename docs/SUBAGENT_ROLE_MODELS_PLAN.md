# 子代理角色模型配置

## Scope

- 给内置委派角色提供用户级默认模型和思考档位。未配置时保留现有行为。
- 模型使用供应商 ID 与模型 ID 的组合标识，不按名字或列表顺序匹配。
- Desktop 角色默认只用于普通委派。Workflow 节点的显式覆盖及恢复缓存保持独立；不把同名自定义角色误当作内置角色。
- 不新增 Agent 写配置工具，不改角色提示词、审批、工具权限、预算或父会话设置。

## Implementation

1. 核对钉住的 Step Code 运行时、Desktop 配置投影和子请求事件。选择运行时已有的角色发现、模型解析和启动边界，不另建执行器。
2. Desktop 主进程负责读写和验证用户配置，renderer 经现有 typed preload；校验角色、精确模型身份和模型支持的档位。只将必要的非密钥配置投影给隔离运行时。
3. 在子进程启动前确定有效模型与来源。显式选择不可用时返回可操作的错误，不回退，不调父会话的 `set_model`。实际值从运行时证据读取；旧记录未知则显示未知，不回填为今天的配置。
4. 设置页复用已有控件和主题。一行一个角色，提供继承、模型与档位；保存状态、失效配置和生效时机可见。保存不重启会话，从下一次新委派读取。
5. 扫描现有验收夹具，先确认普通委派父模型隔离，再覆盖角色选择、显式失效、Workflow 覆盖以及实际结果。用本地模拟供应商核对发送请求，不使用真实账号。增加纯 renderer 浏览器预览，复用生产组件与样式，标明数据是示例。

## Acceptance

- 缺省继续继承；`explore` 与 `review` 可以使用不同供应商/模型/档位。
- 父会话委派前后的实际请求、会话状态及选择器保持原模型和档位。
- 不存在的目标模型、撤销的供应商或不支持的档位不会由另一个模型运行为成功；历史展示不把配置当作实际用量。
- Workflow 节点显式覆盖不退化；读写权限与现有工作树改动不受影响。
- 类型检查、相关测试、真实运行时夹具和内置浏览器预览均有可核查结果。

## Review Decisions

- 上游 CLI 允许部分名称匹配，也可能调整不支持的档位。必须先读取子进程 RPC 实际状态，精确核对供应商、模型和档位，再发送任务。
- 普通委派按批次读取一次配置，已启动和可继续回复的子进程保留启动模型。子代理详情只在核对过的运行时状态和实际子回复身份吻合时展示用模证据；档位是本地运行时档位，不是供应商映射后的原始请求字段。
- 运行时钉点不变。新集成补丁加入 v017 清单并在干净上游工作树回放。共享 `Desktop/runtime` junction 不作为本次构建目标。
