# 主题包作者快速入门

这份指南面向新主题作者。先从 [可安装 v2 起步包](../examples/plugins/theme-starter/README.md)
开始；精确字段、资源和生命周期约束见 [主题组合协议](THEME_COMPOSITION.md)
与 [JSON Schema](plugin-schemas/dfsc.theme.schema.json)。
需要包含该协议的宿主构建，不代表所有已发布客户端已支持。

主题组合协议与个人图片编辑器是两层能力：主线协议负责加载主题和声明插槽；
个人图片导入、编辑及分区材质由宿主管理，本分支已将入口内置到「设置 → 外观」，
不再要求安装自定义背景插件。包含 #223 但尚未内置入口的旧构建仍走旧插件配置页；
仅验证默认主题时不需要背景插件。两种入口都遵守相同的主题插槽规则，
不因本指南或起步包交付就使旧安装包自动具备这些能力。

## 先分清三件事

| 决策 | 声明 | 含义 |
| --- | --- | --- |
| UI 皮肤 | `ui.renderer` | 当前可选宿主标准 UI 或星辰 UI，不是上传自己的 CSS/React |
| 默认底图 | `background.renderer`、`source` | 没有个人替换时，用纯色、包内图片或宿主星辰场景 |
| 可替换范围 | `background.accepts` | `["image-v1"]` 允许个人图片；省略或 `[]` 保持关闭 |

三者独立。默认用图片不意味着允许替换，使用标准 UI 也不意味着必须允许替换。
新主题统一用 v2：可组合与一体化主题都是合法选择，不以开放插槽为上架条件。
旧 v1 保持星辰 UI 与场景绑定，额外塞入 `accepts` 不会升级它。

**底图插槽不是 UI 材质插槽。** 接受个人图片不授权插件改动文字、控件或
主题自己的玻璃/石墨材质。在包含自定义背景分区材质能力的宿主构建中，
标准 UI 可使用该适配提供的分区透明度；
星辰 UI 保留自己的材质，不因接受图片就自动继承这些调节。
不要向清单添加未支持的 `opacity`、`decoupled` 等字段。

## 从起步包做第一个主题

1. 复制 `examples/plugins/theme-starter` 到自己的开发目录。
2. 修改资源目录名、`step.plugin.json` 的 `id` 和本地市场条目的 `name/source`，
   三处使用同一稳定标识。正式投稿不保留示例身份。
3. 修改主题名称、署名和色板，替换 `background.png`、`icon.png`，
   为所有素材提供可再分发的授权。图标是至多 128 KiB、边长至多 512 的 PNG。
4. 在新 DFSC 的「插件 → 市场来源」添加市场根目录的绝对路径，安装插件。
5. 到「外观 → 主题包」选择主题。安装成功不等于已启用，也不等于主题声明有效。

资源结构：

```text
my-theme/
  step.plugin.json       原生身份、版本和资源声明
  dfsc.theme.json        UI、默认背景、可替换范围和色板
  dfsc.plugin.json       作者、分类、依赖和使用说明
  background.png         image-v1 使用的本地资源
  icon.png
  README.md
  LICENSE
```

纯数据主题显式写 `"skills": []`、`"commands": []`、`"agents": []`，
且不声明 MCP 或执行入口。分类 `themes` 只用于展示，不授予能力或安装豁免。
需要 MCP 的混合插件仍需按普通可执行插件审核和停机规则处理。

起步包的完整 `dfsc.theme.json` 可直接使用。最关键的部分是：

```json
{
  "ui": { "renderer": "standard-v1" },
  "background": {
    "renderer": "image-v1",
    "source": "background.png",
    "accepts": ["image-v1"]
  }
}
```

这是完整清单的一部分，不能单独替代 `schemaVersion`、`name`、`scheme` 与八个色板字段。
改为纯色时使用 `{"renderer":"solid-v1","accepts":["image-v1"]}`，不写 `source`。
保留不可替换的整体设计时，将 `accepts` 写为 `[]` 即可。

## 资源与限制

当前只支持静态 PNG/JPEG，不支持 WebP、APNG、视频、HTML、远程图片或任意脚本。
默认图片文件名只能是 `background.png` 或 `background.jpg`；
个人导入支持 `.jpeg`，不表示主题清单也能用这个资源文件名。

| 层次 | 限制 |
| --- | --- |
| 宿主主题清单 | UTF-8 JSON，至多 32 KiB |
| 宿主静态图片 | 输入及解码转存后的 PNG 均至多 12 MiB；单边至多 8192；像素至多 33,554,432 |
| 社区市场同步 | 每个文件至多 8 MiB、每包至多 32 MiB、至多 1000 文件，包含文档和素材 |
| 可选主题封面 | `cover.png`，至多 512 KiB，宽至多 1920、高至多 1080 |

**向社区投稿按更严格的 8 MiB 单文件限制准备资源。**
即使文件小于 8 MiB，也可能在宿主解码转 PNG 后超过 12 MiB；
静态检查不能保证原生解码成功。宿主不会通过偷偷缩图来满足限制。
色板的 `ink`、`muted` 对 `bg`、`side`、`surface`、`code` 都须达到 4.5:1 对比度。
这不等于任意背景上的阅读体验已经合格，仍须检查真实画面。

## 开放插槽后的行为

- 无替换时使用主题默认背景。
- 主题接受 `image-v1`，且个人图片已启用并成功解码时，才替换底图。
- 替换会释放旧场景，不应让两个背景在后台同时运行；不会切换主题或移除 UI 皮肤。
- 主题不接受替换时继续显示默认背景，个人图片与参数保留。
- 关闭个人背景回到主题默认背景；图片失效不能让旧渲染器隐形运行。

“已安装”“允许替换”“个人图片已启用”“实际正在使用”是不同状态。
文档和截图不要把保存成功当作背景已经应用。

## 投稿前自检

在社区市场源码目录运行以下命令，路径替换为自己的插件资源根目录：

```sh
node scripts/check-theme-pack.mjs --package /absolute/path/to/my-theme
```

该主题专项检查在社区市场 CI 中也会读取同步后的包。
它检查清单、受支持的组合、色板对比度、资源存在性和图片头部边界，
不执行包代码，不代替原生解码、素材授权、平台兼容性或视觉验收。
新检查尚未随旧市场源码交付时，请取得包含它的提交，不要把“找不到脚本”当作通过。

至少记录以下原生验收，而不是只贴清单或校验绿灯：

- 发现、安装、到外观中选择；重启后主题仍正确；停用与卸载能恢复内置主题。
- 对开放插槽的主题：在包含个人图片适配的构建上验证默认底图 → 个人图片 →
  跟随主题，UI 与主题色保持不变。没有该适配时记录“个人图片替换未验证”。
- 对关闭插槽的主题：明确提示不支持替换，图片保留，不叠加第二个场景。
- 明暗要求、窄窗口、长文本、代码、菜单、审批、输入框和键盘焦点可读。
- 有动态场景时检查关闭动态、减少动态、窗口隐藏、替换后停止工作。

写明实际宿主提交/构建与平台。版本号相同不证明拥有同一批能力，
不能照抄 `requirements.dfsc` 或把未测试的平台写成支持。
固定提交、资源同步与收录流程见社区市场的 `CONTRIBUTING.md`；
市场 README 会覆盖资源根 README，需要保留专用作者说明时放在包内 `docs/`
并通过 `dfsc.plugin.json` 指定。

## 从 v1 迁移与新范式

迁移须显式改成 `schemaVersion: 2`，把顶层 `renderer`、`scene` 删除，
分别设置 `ui.renderer` 和 `background.renderer/source`，再决定 `accepts`。
先验证原始外观，再验证开放的替换组合，不把 v1 默认关闭当成缺陷强行放开。

目前只有宿主已经实现的 `standard-v1`、`stellar-v1` UI，以及纯色、图片、
星辰场景背景。作者可以提出新引擎与交互原型，但新 renderer 需另行接入宿主，
明确数据、生命周期、资源与输入边界后版本化支持。
协议统一的是连接方式与所有权，不要求所有创意都变成静态图片；
现有插槽也不预先授予 HTML、键盘接管或脚本执行能力。
