# 桌面结构化提问 Beta

## 功能与边界

DFSC 为上游 `clarify_user` 增加了桌面 RPC 兼容层。它不是上游已经支持的
桌面协议，因此提问抽屉、正文工具记录和脉冲入口均标注 **Beta**。
现有提问权限规则保持不变，允许提问不等于代替用户回答。

模型工具名、参数和正常结果沿用上游。支持单题、整组问题、单选和允许时的
自由输入。单选后自动下一题，最后一题需明确提交；可以前后翻题修改，
整组提交前检查漏答。多选、逐题跳过、推荐选项没有上游契约，不自行增加。

正文保留等待、已回答、取消或失败的工具记录。等待期间可从正文或脉冲入口
重新打开审批风格抽屉。收起不取消，当前进程内切换会话保留草稿。
提交失败保留草稿并允许重试。

## 兼容补丁

基线为 `3ba89e0cbfe6be78cccdafb5aeafd2592177cbb8`。
`patches/step-code-desktop-clarification.patch` 仅修改 `step-questionnaire.ts`：

- 注册 opt-in `--desktop-clarification`，仅 DFSC 主会话启动时传入；
  普通 CLI/TUI 和 RPC 子代理不启用此传输。
- 使用现有可取消 `ui.input` RPC 将完整问题组封装为版本化 JSON。
  固定标题前缀用于识别传输，不作为面向用户的标题。
- 关联原始工具调用 ID；整组答案作为 JSON 字符串返回。
  主进程和运行时验证题目顺序、ID、选项值及自由输入权限。
  选项显示文本和索引由运行时从原问题重建，不信任前端提供的标签。
- 复用原始工具结果、取消结果和遥测，不改变模型决策策略。
  工具结束或本轮结束清理悬挂的桌面入口。

补丁有原始源文件、补丁内容及暂存后源文件的哈希检查。不得通过修改
个人 Step Code checkout 或仅修改生成 bundle 来替代可复现补丁。

## Plan 关联

上游 Plan 已包含 `clarify_user`。本次复用共享提问能力，不强制每份计划都提问，
不添加“回答即批准”的语义。问题回答后仍需通过原有 `exit_plan_mode` 批阅。
提问与计划批阅共用视觉语言，但请求、结果和授权互相独立。

## 无人值守尚未扩展

没有自动代答、超时同意或超时继续其他任务。未回答时该工具继续等待。
当前草稿不跨应用重启恢复，也不承诺被停止的原始提问可重新提交。
答案和取消结果属于上游会话历史；未回答问题不是持久化任务系统。
这是需要模拟体验并向上游反馈的边界，而不是已解决的无人值守机制。

## 后续上游建议

先在本仓库建立 Issue 跟踪以下扩展边界，再视体验结果向上游提建议：

- 多选：明确题型参数与多值答案，不把复选框结果塞进现有单选字符串。
- 逐题跳过：区分暂时翻到下一题与明确不回答；原生界面和当前桌面实现
  均要求全部答齐后提交，取消会结束整组，不具备独立的跳过结果。
- 当前桌面 RPC 兼容层及无人值守、重启恢复需求：保持 Beta 标注，
  不擅自代答、不把超时视为批准。
