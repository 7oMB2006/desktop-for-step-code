## 演练发现的骨架问题

从「发现」页打开一个已安装插件的设置时，宿主曾误用市场预览引用，
把它当成没有配置表单。示例没有绕过该限制。

已在宿主的共享 `PluginCenter` 修正：文档仍保留所选市场快照，
配置使用其对应的安装实例引用。该修复适用于所有声明式配置插件，
没有增加本文本工具的专用逻辑。
浏览器回归使用原有的配置 starter 覆盖该入口，真实 Electron 也已复测。

首次测试脚本还修正了旧 runtime 工作目录、字段 ID 大写、
导航角色及等待时序；Windows 卸载测试的外部 MCP 客户端不再把工作目录
设在将被删除的插件内。它们不是放宽宿主校验的理由。

## 复跑

独立源码的业务、协议与资源检查：

```sh
npm test
```

真实宿主验收脚本为 `tests/dfsc-acceptance.mjs`，接受三个绝对路径参数：
`--desktop` 指向有开发依赖的 Desktop 目录，`--main` 指向骨架构建的
`main.cjs`（同目录必须有相匹配的 `runtime/`），`--output` 必须是全新目录。
它会使用隔离 profile，不读写日常账户；成功后卸载测试插件并退出。

本轮最后验收目录与准确构建位置记录在 DFSC 的 `docs/VERIFICATION.md`。
`screenshots/` 是该次成功验收复制出来的原图。
